# DeepInfer cache and computation precision

Date: 2026-11-04. This study uses first-party public source and model configuration for the NVIDIA SM100 path. No upstream program, build, model, or GPU measurement was run.

## Findings and revisions

The first-party implementation is `deepseek-ai/DeepInfer`. DeepSeek's [release Q&A](https://github.com/deepseek-ai/DeepInfer/blob/a679bb86ce36e883a98a97733492b686e5b9a08e/doc/inference_deployment_qa.md#L17-L21) identifies this repository and its V4.1 Flash use. The [configuration reader](https://github.com/deepseek-ai/DeepInfer/blob/a679bb86ce36e883a98a97733492b686e5b9a08e/deepinfer/hugging_face/config.py#L245-L253) checks `deepseek_v41`. The default checkpoint is the official [DeepSeek-V4.1-Flash-1017](https://github.com/deepseek-ai/DeepInfer/blob/a679bb86ce36e883a98a97733492b686e5b9a08e/README.md#L65-L69). The fixed configuration gives the dimensions and the shared layers. The project name is not the source for this information.

The examined main revision is `a679bb86ce36e883a98a97733492b686e5b9a08e`. Its [dependency tree](https://github.com/deepseek-ai/DeepInfer/tree/a679bb86ce36e883a98a97733492b686e5b9a08e/vendor) gives FlashMLA `2e5429fc5653bab6e081f09477126f731882a6a9` and DeepGEMM `1fc9c66975ee322d628b3288534ca0e9ce12a64d`. All source links use these revisions. The official model configuration revision is `1bae0e1088993b9b82de08f59de5be5a34e42170`.

Global KV storage defaults to FP4. Main attention uses BF16 operands and FP32 accumulation. The indexer uses MXFP4 QK instructions. The statements "all FP4" and "all BF16" are not sufficient. See [defaults](https://github.com/deepseek-ai/DeepInfer/blob/a679bb86ce36e883a98a97733492b686e5b9a08e/deepinfer/hugging_face/config.py#L299-L306), [attention instructions](https://github.com/deepseek-ai/FlashMLA/blob/2e5429fc5653bab6e081f09477126f731882a6a9/csrc/cuda_kernels/sm100/prefill/sparse/fused_norm_rope_attn_rope_cast_fwd/core_attn/config.h#L251-L264), and [indexer instructions](https://github.com/deepseek-ai/DeepGEMM/blob/1fc9c66975ee322d628b3288534ca0e9ce12a64d/deep_gemm/include/deep_gemm/impls/sm100_mqa_logits.cuh#L371-L380).

## Persistent cache formats

An entry below is one cache vector, not one original token across all layers. Quantization precision gives decoding rules. `uint8` and `int8` are physical containers for encoded data.

| Cache | Numerical format and groups | Net bytes per entry | Layout and source |
|---|---|---:|---|
| Global compressed KV, default | 512 E2M1 FP4 values, one E4M3 scale per 16 values | 256 + 32 = 288 | `uint8`, `[data \| scale]` per entry, [definition](https://github.com/deepseek-ai/DeepInfer/blob/a679bb86ce36e883a98a97733492b686e5b9a08e/deepinfer/model_executor/layers/tilelang_ops/cache_common.py#L119-L128) |
| Index keys | 128 E2M1 FP4 values, one UE8M0 exponent scale per 32 values | 64 + 4 = 68 | The block data is before the block scales. [definition](https://github.com/deepseek-ai/DeepInfer/blob/a679bb86ce36e883a98a97733492b686e5b9a08e/deepinfer/model_executor/layers/tilelang_ops/cache_common.py#L129-L137) |
| SWA window | 512 E4M3 FP8 values, one UE8M0 scale per 32 values | 512 + 16 = 528 | `uint8`, `[data \| scale]` per entry, [definition](https://github.com/deepseek-ai/DeepInfer/blob/a679bb86ce36e883a98a97733492b686e5b9a08e/deepinfer/model_executor/layers/tilelang_ops/cache_common.py#L109-L118) |
| Global KV, FP4 disabled | SWA's FP8 format | 528 | Selected by `use_fp4_sparse_kv`, [selection](https://github.com/deepseek-ai/DeepInfer/blob/a679bb86ce36e883a98a97733492b686e5b9a08e/deepinfer/worker/cache_engine.py#L46-L56) |

FP4 uses floating-point E2M1 encoding, with two values per byte, not four-bit integers. Global scales are one-byte E4M3. Index scales are one-byte UE8M0, with four bytes packed into an `int32` at some interfaces. These scales are not interchangeable. All 512 global dimensions are quantized, with 64 RoPE dimensions and no BF16 tail. See [physical views](https://github.com/deepseek-ai/DeepInfer/blob/a679bb86ce36e883a98a97733492b686e5b9a08e/deepinfer/model_executor/layers/tilelang_ops/cache_common.py#L275-L328) and [FlashMLA constants](https://github.com/deepseek-ai/FlashMLA/blob/2e5429fc5653bab6e081f09477126f731882a6a9/csrc/cuda_kernels/kv_cache_format.h#L5-L19).

The global FP4 writer calculates group absolute maxima, clamps `amax / 6`, and rounds the scale to E4M3. It uses that rounded scale's reciprocal for E2M1 encoding, without an extra FP32 global scale. Index keys use UE8M0 rules. See the [writer](https://github.com/deepseek-ai/DeepInfer/blob/a679bb86ce36e883a98a97733492b686e5b9a08e/deepinfer/model_executor/layers/tilelang_ops/cuda/store_kv_cache.py#L141-L184).

KV source layers are `2/8/14/20`, with compression ratios `2/2/2/1`. Index computation has eight source layers. Without separate `index_k_source_layer_ids`, index keys follow the four KV sources. Eight key copies are not allocated. See [model configuration](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash-1017/blob/1bae0e1088993b9b82de08f59de5be5a34e42170/config.json#L60-L123) and [sharing maps](https://github.com/deepseek-ai/DeepInfer/blob/a679bb86ce36e883a98a97733492b686e5b9a08e/deepinfer/hugging_face/config.py#L62-L85).

Consumers reference source `ica_cache` or `ca_cache` without increasing that allocation's offset. Global cache shape is `[num_pages, block_size / ratio, 1, bytes_per_entry]`. Index sections use 32-byte alignment. Pages use `lcm(128, main_bytes_per_entry)`. SWA rings occupy separate sequence state slots. See [allocation](https://github.com/deepseek-ai/DeepInfer/blob/a679bb86ce36e883a98a97733492b686e5b9a08e/deepinfer/worker/cache_engine.py#L406-L484) and [128-byte alignment](https://github.com/deepseek-ai/DeepInfer/blob/a679bb86ce36e883a98a97733492b686e5b9a08e/deepinfer/model_executor/model_metadata_utils.py#L137-L140).

Persistent caches have no full-history BF16 expanded copy. Sources with compression above 1 also have FP32 compression rings: `[state_slots, ring_size, 2, dim]`. These hold compression and rollback state, without linear growth with total context length. See [fields](https://github.com/deepseek-ai/DeepInfer/blob/a679bb86ce36e883a98a97733492b686e5b9a08e/deepinfer/worker/cache_engine.py#L205-L218), [ring length](https://github.com/deepseek-ai/DeepInfer/blob/a679bb86ce36e883a98a97733492b686e5b9a08e/deepinfer/worker/cache_engine.py#L119-L133), and [FP32 views](https://github.com/deepseek-ai/DeepInfer/blob/a679bb86ce36e883a98a97733492b686e5b9a08e/deepinfer/worker/cache_engine.py#L367-L374).

## Reads during prefill, decode, and speculative verification

| Path | Read and expansion | Computation |
|---|---|---|
| Main attention prefill | Paged FP4 global KV and FP8 old windows expand into contiguous BF16 buffers. The kernel quantizes and expands the current windows | BF16 Q/K/V, FP32 QK and PV tensor core accumulation |
| Main attention decode | Separate FP8 SWA and FP4 global caches enter FlashMLA. Selected entries expand into BF16 registers and shared memory | BF16 Q/K/V, FP32 QK and PV accumulation |
| Target speculative verification | Decode metadata has space for `nextn + 1` query rows. The non-prefill branch applies | Same cache formats and instructions as decode |
| Indexer prefill | Extracted codes and scales stay FP4, without full BF16 key expansion | MXFP4 QK, FP32 dot accumulation, BF16 head weighting and reduction |
| Indexer decode and verification | DeepGEMM scores paged codes directly, with optional candidate blocks | Same arithmetic, BF16 scores for selection |

Call evidence: [two-cache decode](https://github.com/deepseek-ai/DeepInfer/blob/a679bb86ce36e883a98a97733492b686e5b9a08e/deepinfer/model_executor/models/v4_modules/attn.py#L628-L669), [prefill loads and branches](https://github.com/deepseek-ai/DeepInfer/blob/a679bb86ce36e883a98a97733492b686e5b9a08e/deepinfer/model_executor/models/v4_modules/attn.py#L812-L877), [current-window quantization](https://github.com/deepseek-ai/DeepInfer/blob/a679bb86ce36e883a98a97733492b686e5b9a08e/deepinfer/model_executor/models/v4_modules/attn.py#L402-L449), [BF16 load output](https://github.com/deepseek-ai/DeepInfer/blob/a679bb86ce36e883a98a97733492b686e5b9a08e/deepinfer/model_executor/layers/tilelang_ops/cuda/load_paged_kv_cache.py#L100-L125), and [speculative query length](https://github.com/deepseek-ai/DeepInfer/blob/a679bb86ce36e883a98a97733492b686e5b9a08e/deepinfer/model_executor/input_metadata/prepare_tensor_input_zos.py#L307-L358).

Instruction evidence: fused [BF16 expansion](https://github.com/deepseek-ai/FlashMLA/blob/2e5429fc5653bab6e081f09477126f731882a6a9/csrc/cuda_kernels/sm100/prefill/sparse/fused_norm_rope_attn_rope_cast_fwd/core_attn/kernel.cuh#L256-L294) and [BF16/BF16/FP32 types](https://github.com/deepseek-ai/FlashMLA/blob/2e5429fc5653bab6e081f09477126f731882a6a9/csrc/cuda_kernels/sm100/prefill/sparse/fused_norm_rope_attn_rope_cast_fwd/core_attn/config.h#L251-L278). Unfused 64-head [prefill](https://github.com/deepseek-ai/FlashMLA/blob/2e5429fc5653bab6e081f09477126f731882a6a9/csrc/cuda_kernels/sm100/prefill/sparse/fwd/head64/config.h#L125-L131) and [decode](https://github.com/deepseek-ai/FlashMLA/blob/2e5429fc5653bab6e081f09477126f731882a6a9/csrc/cuda_kernels/sm100/decode/sparse/head64/config.h#L174-L181) use the same types. The parameter name `is_fp8_kvcache=True` does not prove global KV is FP8. [Format rules](https://github.com/deepseek-ai/FlashMLA/blob/2e5429fc5653bab6e081f09477126f731882a6a9/csrc/cuda_kernels/kv_cache_format.h#L37-L54) let FlashMLA use an FP8 cache plus an FP4 extra cache.

Main softmax scores, maxima, and denominators use FP32. Exponent results round to BF16 before PV. The default fused path, when selected, outputs E4M3 with per-32 UE8M0 scales for the next projection. FP32 accumulation does not keep all intermediate values as FP32. See [softmax](https://github.com/deepseek-ai/FlashMLA/blob/2e5429fc5653bab6e081f09477126f731882a6a9/csrc/cuda_kernels/sm100/prefill/sparse/fused_norm_rope_attn_rope_cast_fwd/core_attn/kernel.cuh#L929-L990), [output format](https://github.com/deepseek-ai/FlashMLA/blob/2e5429fc5653bab6e081f09477126f731882a6a9/csrc/cuda_kernels/sm100/prefill/sparse/fused_norm_rope_attn_rope_cast_fwd/core_attn/config.h#L28-L36), and [selection conditions](https://github.com/deepseek-ai/DeepInfer/blob/a679bb86ce36e883a98a97733492b686e5b9a08e/deepinfer/model_executor/models/v4_modules/attn.py#L85-L92).

The indexer quantizes Q to FP4. Prefill loads return codes and scales, and decode passes paged storage. See [Q and K handling](https://github.com/deepseek-ai/DeepInfer/blob/a679bb86ce36e883a98a97733492b686e5b9a08e/deepinfer/model_executor/models/v4_modules/index_attn.py#L164-L202), [prefill](https://github.com/deepseek-ai/DeepInfer/blob/a679bb86ce36e883a98a97733492b686e5b9a08e/deepinfer/model_executor/models/v4_modules/index_attn.py#L284-L325), and [paged calls](https://github.com/deepseek-ai/DeepInfer/blob/a679bb86ce36e883a98a97733492b686e5b9a08e/deepinfer/model_executor/models/v4_modules/index_attn.py#L421-L454). DeepGEMM uses E2M1/UE8M0 [block-scaled FP32 accumulation](https://github.com/deepseek-ai/DeepGEMM/blob/1fc9c66975ee322d628b3288534ca0e9ce12a64d/deep_gemm/include/deep_gemm/impls/sm100_mqa_logits.cuh#L371-L419) and [MXFP4 block32 instructions](https://github.com/deepseek-ai/DeepGEMM/blob/1fc9c66975ee322d628b3288534ca0e9ce12a64d/deep_gemm/include/deep_gemm/ptx/tcgen05.cuh#L124-L145). The kernel applies ReLU to dot results, converts them to BF16, then uses BF16 head weights for multiply-add and reduction. See [ordinary scoring](https://github.com/deepseek-ai/DeepGEMM/blob/1fc9c66975ee322d628b3288534ca0e9ce12a64d/deep_gemm/include/deep_gemm/impls/sm100_mqa_logits.cuh#L440-L516) and [candidate scoring](https://github.com/deepseek-ai/DeepGEMM/blob/1fc9c66975ee322d628b3288534ca0e9ce12a64d/deep_gemm/include/deep_gemm/impls/sm100_sparse_mqa_logits.cuh#L568-L625).

## Capacity for 64 sequences of 800000 tokens

The official sources and ratios give `800000 / 2 * 3 + 800000 = 2000000` entries per sequence. Each entry uses `288 + 68 = 356` bytes.

| Item | Net bytes across 64 sequences | GiB |
|---|---:|---:|
| Global KV | 36864000000 | 34.332275 |
| Index keys | 8704000000 | 8.106232 |
| Combined | 45568000000 | 42.438507 |
| Plus 40 layers of 128-slot SWA | 45741015040 | 42.599640 |
| Plus 43 layers of 128-slot SWA | 45753991168 | 42.611725 |

Here, `1 GiB = 2^30` bytes. Calculations use the official [40-layer/window configuration](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash-1017/blob/1bae0e1088993b9b82de08f59de5be5a34e42170/config.json#L27-L60), [three prediction layers](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash-1017/blob/1bae0e1088993b9b82de08f59de5be5a34e42170/config.json#L145-L155), and the cache formats above. The 43-layer row adds three draft windows, not three global histories. [Layer construction](https://github.com/deepseek-ai/DeepInfer/blob/a679bb86ce36e883a98a97733492b686e5b9a08e/deepinfer/hugging_face/config.py#L136-L155) assigns window attention to them.

These are logical payloads, not allocated memory or total runtime capacity. Allocations add rollback slots, state slots at default ratio `1.2` plus one slot, page alignment, FP32 compression state, weights, and workspaces. See [window length](https://github.com/deepseek-ai/DeepInfer/blob/a679bb86ce36e883a98a97733492b686e5b9a08e/deepinfer/worker/cache_engine.py#L88-L110), [state slots](https://github.com/deepseek-ai/DeepInfer/blob/a679bb86ce36e883a98a97733492b686e5b9a08e/deepinfer/worker/cache_engine.py#L201-L218), and [defaults](https://github.com/deepseek-ai/DeepInfer/blob/a679bb86ce36e883a98a97733492b686e5b9a08e/deepinfer/environ.py#L135-L171).

Prefill has large temporary expansion. `_prepare_prefill_kv` allocates `[total_kv, 1, 512]` BF16 storage, reuses it across consumers, and releases the previous source segment before allocation. If one call loads 64 histories of 800000 tokens without context-parallel partitioning, the ratio-1 source alone uses `64 * 800000 * 512 * 2 = 48.828125 GiB`. The window data uses more storage.

This is conditional arithmetic, not a measured peak. The four source expansions are not all resident at the same time. See [allocation and release](https://github.com/deepseek-ai/DeepInfer/blob/a679bb86ce36e883a98a97733492b686e5b9a08e/deepinfer/model_executor/models/v4_modules/attn.py#L723-L750) and [lengths and loads](https://github.com/deepseek-ai/DeepInfer/blob/a679bb86ce36e883a98a97733492b686e5b9a08e/deepinfer/model_executor/models/v4_modules/attn.py#L812-L842). Query chunking alone does not necessarily bound history-key expansion. The total loaded keys must also be bounded.

## Applicable ideas and uncertainties

Candidate changes are encoded persistent KV with four source owners, explicit scale/page contracts, decode expansion on selected reads, and a separate prefill expansion budget. These ideas use the allocation, format, and read paths given above. Implementation and numerical validation in this repository are still necessary. This study proves no bitwise equivalence with the current computation order and implements no product code.

Physical caches and read kernels are public. The complete production KV system and load balancing are not fully open-source. See [release scope](https://github.com/deepseek-ai/DeepInfer/blob/a679bb86ce36e883a98a97733492b686e5b9a08e/doc/inference_deployment_qa.md#L19-L21) and [missing service components](https://github.com/deepseek-ai/DeepInfer/blob/a679bb86ce36e883a98a97733492b686e5b9a08e/README.md#L38-L42). Production replication, tiered-cache memory, and per-GPU sequence capacity cannot be derived here. Ascend kernels, kernel selection in a binary, numerical results, and measured deployment capacity were not verified.
