# 类型化模型执行

## 范围

[组 client](../../crates/zmq-worker/src/rank_client/model.rs) 将类型化调度器输入连接到四 rank 执行.
模型策略提供 `ModelState<L>`, 包含事务 key, 读取块, 写入块和模型选择的布局 `L`.
共享 client 不解释物理张量布局.
Qwen 服务保留现有 client 和传输格式.
尚未启用 DeepSeek 模型执行.

[事务策略](../../crates/scheduler/src/policy.rs) 扩展共享缓存策略.
其 detach 操作将活动状态事务从策略转交给组 client.
其 restore 操作交还这些所有者, 但不发布已接受状态.
每个操作必须先验证完整身份集合, 再改变所有权.
这些回调是受信任的模型代码, 不是 worker 消息.

## 输入和所有权

`execute_scheduled` 接收调度器, 其已调度批次和步骤计划.
client 检查请求顺序, 已调度 token 切片, 已计算位置, 行数和 prefill 决策.
每个输入 token 必须小于词表大小.
已计算结束位置不得超过描述符的上下文限制.
rank gate 检查组请求上限, 行数上限和事务身份.
它验证集合通信计划和完成元数据, 而不是 worker 内部的原生调用顺序.

每个状态 key 必须等于活动事务 key.
写入绑定必须包含事务分配的全部块, 不得包含其他块, 且不能重复.
读取绑定必须来自事务的读取或写入所有者, 且不能重复.
绑定必须与协商后的公共缓存 schema, rank 放置, 槽位容量和代次一致.
复制的元数据不能创建存储所有权.

模型布局只能使用已声明的绑定.
共享 client 无法检查任意布局类型内的引用.

client 在第一次异步等待之前持有分离的所有者.
此后调度器拒绝直接更新, 并且不再调度更多工作.
已中止请求可以释放其请求所有者, 但不能释放 client 的事务所有者.

## 传输格式

组协议版本 3 添加 `execute_model` 和 `model_result`.
仅元数据执行仍然可用.
两条执行路径都拒绝另一类型的回复.

`execute_model` 命令包含普通步骤分发, SHA256 摘要和二进制 msgpack 载荷.
载荷包含已调度 token 分块, 已计算位置, 类型化状态分配, 以及已完成和已抢占请求 ID.
它不包含完整提示历史.
模型准备和历史传输使用不同的生命周期集成.

序列化在载荷超过 64 MiB 之前停止.
所有序列化映射和序列都必须具有已知长度.
递归序列化检查在 msgpack 可以分配临时容器存储之前拒绝未知长度.
因此, 模型布局不能使用 `serde(flatten)` 或未知长度迭代器.
字符串必须在序列化之前准备好.
此检查拒绝 `collect_str` 格式化.

命令上限为分发元数据额外允许 1 MiB.

每个 rank 回复仍限制为 1 MiB.
SHA256 根据序列化载荷字节计算, 而不是根据重建后的字典计算.
它检测不一致, 但不认证 worker 身份.

## 完成和发布

每个 rank 返回完成记录和载荷摘要.
每个 rank 仅为自己拥有的请求返回模型输出.
TP4 和 TEP4 使用输出所有者 rank 零.
DEP4 使用每个请求已调度的所有者 rank.
没有本地请求的 rank 也必须确认完成.

client 拒绝缺失结果, 重复结果和无效 token.
它还拒绝发送 rank 不拥有的请求的结果.
结果 token 数和草稿数必须满足描述符的推测执行限制.
rank gate 在发布可以继续之前验证全部完成记录.

随后调度器对照其执行中请求验证完整输出, 包括已调度草稿和预期的已验证 token 数.
只有通过这些检查后, 策略才接收其事务, 并通过现有更新路径选择已接受状态.
输出顺序与调度器的请求顺序相同, 而不是回复到达顺序.

## 失败和取消

任何执行错误都会禁用调度器的执行路径.
它还会启动组关闭, 并等待所属进程终止后才返回错误.
失败批次中的任何有效子集都不会成为已接受状态.

取消执行 future 会使调度器保持禁用, 并使 client 继续持有其事务.
调用 `close`.
替换之前等待终止.
丢弃 client 会启动相同的后台清理.
替换时使用新调度器和 epoch.
[进程所有权指南](rank-supervisor.zh.md) 规定清理和关闭边界.
