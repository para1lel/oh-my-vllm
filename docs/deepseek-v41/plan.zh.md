# DeepSeek V4.1 实施计划

## 目标和状态

在四张 B200 上加入 DeepSeek 推理, 支持全部适用的 Qwen 功能.
[架构](design.zh.md) 和[验收范围](validation.zh.md) 已获批准.
在 `nightly` 连续开发, 无需逐阶段审批.
DeepSeek 服务推理尚未启用.

阶段 1 和 2 已实现.
阶段 0 的参考与分配工作仍在继续.
阶段 3 已有独立的精确量化和 Engram 哈希算子.
完整模型计算与阶段 4-8 尚待完成.

## 约束

- 代理使用 GPT-6.1 Sol 和 `high` effort.
- 排除物理 GPU 0.
- 保留 Qwen 普通解码, MTP4, 262144 总 tokens 及单张 B200 配置.
- 加入 TP4, TEP4, DEP4, 最多五个草稿的 DSpark, 64 个已接纳请求及每请求 1048576 总 tokens.
- Engram 权重保存在一个共享 pinned-host 存储中.
- 保留 Rust 调度与状态所有权, Python GPU 控制, ZMQ DEALER 和 msgpack.
- 使用 native CUDA 算子, 不加入外部算子库或 vLLM 依赖.
- 对每条完整 Execute 消息应用 [Eager/Graph 执行规则](../execution.zh.md).
- 遵守[交付流程](../../CONTRIBUTING.zh.md) 和[报告规则](validation.zh.md#结果与交付).

## 阶段门槛

每个算子在实现前必须有冻结的数学定义, 夹具和数值限值.
复合限值和长参考待完成时, 可推进独立的精确转换与整数哈希.
此例外不允许在延迟限值冻结前做性能调优.
它不允许在适用的阶段 0 门槛关闭前集成完整模型.

不要修改活跃参考生成器使用的源码或环境.
候选实现验收时, 保持已有数值夹具和限值不变.
新增测试前, 向维护者说明已有检查为何不足.
已有测试覆盖所需行为时, 复用已有测试.

每次交付都需要独立审查, 修正问题, 运行适用 hooks, 按文件提交并推送 `nightly`.
明确记录进程与 GPU 锁的所有权.
临时进程完成工作后必须停止.
只保留当前说明和最近一次完整的获准测量.

## 阶段 0: 参考和分配契约

已完成的前置工作:

- 检查全部 48 个分片, 张量布局, 尺度和源码身份.
- 定义[模型数学](model.zh.md), [状态所有权](state.zh.md), [采样](sampling.zh.md) 和[媒体编码](video.zh.md).
- 保存独立的[短文本, DSpark, 媒体, 编码及精确算子夹具](fixtures.zh.md).
- 实现逐层 FP64 参考生成和独立的发布源码捕获工具.
- 定义三种并行策略和精确测量矩阵.

下一步工作:

- 完成并冻结[长上下文参考](long-reference.zh.md).
- 调优前冻结复合数值限值和算子延迟限值.
- 关闭[分配计划中的未决边界](memory.zh.md#6-分配上限与未决边界), 覆盖上下文上限下的 64 个请求.

门槛: 不得有影响阶段 3 算子的未决权重映射或验收规则.
已有 Qwen 参考不覆盖这些格式或状态方程.

## 阶段 1: 模型适配器

已实现的[适配器](adapters.zh.md) 选择描述符, 缓存 schema, 并行计划, 推测, 编码器和模型执行.
Qwen 专用维度与策略位于其模型包中.
未知架构, 不支持的格式和能力不匹配必须报错.

门槛: Qwen 通过适配器后保留 API 行为, 已接受输出和状态语义.
保留已有 Rust, 服务, 约束, 执行和冻结数值检查.

## 阶段 2: 类型化状态与 rank 控制

已实现的[分布式基础设施](distributed.zh.md) 提供类型化事务, 组 epoch, 就绪, 完成, 截止时间和关闭.
GPU 选择必须取得全部所需锁, 或在等待前释放它们.
集合通信计划规定 Eager 与 Graph 执行的顺序和缓冲区生命周期.

门槛: 四 rank 合成执行不能发布部分状态或泄漏进程和锁.
检查覆盖空 rank, 不均衡调度, 过期结果, 启动失败和集合通信失败.
DeepSeek 物理状态选择属于后续工作.

## 阶段 3: 权重与算子

- 使用固定夹具实现 FP8/FP4 投影, 路由, 超连接, 压缩和稀疏注意力.
- 仅加载 rank 所属切片, 不完整展开为 FP16 或 FP32.
- 通过共享 pinned 存储和有界暂存实现 Engram 查找.
- 分开核算 Engram 存储和主机 KV.
- 检查注册, NUMA 放置, 内存压力, 取消和传输所有权.
- 运行数值检查, 固定延迟检查, 并对变更的内存路径运行 Compute Sanitizer.

使用已有 API/plan/workspace 结构.
权重计划使用检查点身份与并行策略.
门槛: 算子符合参考且满足启动预算.

## 阶段 4: 普通推理

减少解码器工作量前, 先实现完整短上下文目标计算.
依次加入 TP4, TEP4 和 DEP4.
将共享专家, 输出头, 视觉和 DSpark 权重绑定到获准的放置计划.

检查专家负载不均, 空 rank, top-k 平分和请求重排.
比较 Eager prefill 与 Graph decode 之后全部 129280 个端点 logits.
门槛: 三种策略均能通过离线和 HTTP 接口服务普通文本.

## 阶段 5: 上下文和容量

实现有界 prefill 分块, 索引工作区, 共享压缩 KV 和私有推测状态.
加入前缀共享, 压力驱动卸载, 精确恢复和部分前缀续算.
对照完整计算验证减少工作量后的解码器.
近似恢复需要单独批准和数值限值.

预留输出容量后, 检查 400000, 800000 和 1048576 总 token 边界.
在每种策略下用普通解码运行 64 个已接纳请求.
检查内存压力下的取消和反复驱逐/恢复.
门槛: 实测分配符合核算, 普通解码容量用例完成.

## 阶段 6: DSpark

实现三个预测层, 最多五个提议和六个目标验证行.
先实现固定长度验证.
固定长度接受通过后再加入置信度调度.
保留精确概率修正.

检查各拒绝位置, 全接受, EOS, 停止条件, 限额, schema 掩码和恢复后的传输.
检查部分验证期间和批次重排后的 RNG 与惩罚历史.
分开表示已提交长度和新提议.
使用已接受的目标特征与状态续算.
在每种策略下用 DSpark 重跑 64 请求容量用例.
门槛: 三种策略均符合采样和状态契约.

## 阶段 7: API 和媒体对齐

通过模型选择的行为完成[功能清单](validation.zh.md#功能清单).
对照固定编码器检查工具, 推理, 续算, 结构化输出以及有序图片/视频输入.
保持公开请求/响应语义和现有限制.

运行 HTTP 流式输出, 离线执行, 取消和 worker 替换.
门槛: DeepSeek 支持每项宣称与 Qwen 对齐的功能.

## 阶段 8: 测量和交付

扩展已有 benchmark 驱动, 支持 DeepSeek profile 和四 rank 身份.
检查精确用例枚举, 提示词/输出长度和完整响应 ID 关联.
正确性门槛通过后, 运行 [38 组 HTTP 和三组 AgentX](validation.zh.md).
单独保留 Qwen 的 24 组回归.

每个完整矩阵完成后, 替换已有结果文档.
将测量绑定到源码, 二进制, 权重, 分词器, 拓扑和配置.
报告实测延迟, 吞吐, 接受率, 内存和失败情况.
不复用 Qwen 效率值, 不虚构吞吐门槛.
门槛: 已审查结果和资源清理适用于交付源码.
