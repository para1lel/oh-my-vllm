# GPU 组租约

## 范围

[Phase 2 计划](plan.zh.md#阶段-2-增加类型化缓存组和四-rank-控制) 规定了一组四张 B200 GPU 的租约.
[并行策略](design.zh.md#并行策略) 使用同一个组.
包装脚本也支持现有的单张 B200 命令.

此更改提供设备选择和协作式文件锁.
它不提供 NCCL 通信, 分布式工作进程控制, 状态事务或容量验收.
Rust 控制调度和逻辑状态.
[执行规则](../execution.zh.md) 适用于后续 GPU 计算.

## 命令和设置

使用现有的命令接口:

```bash
scripts/with-env.sh scripts/with-gpu.sh COMMAND [ARGS...]
```

在此命令之前设置环境变量.
将主机设置放在忽略的 `LOCAL.md` 中.

| 变量 | 含义 |
|---|---|
| `OH_MY_VLLM_GPU_COUNT` | `1` 或 `4`. 默认值为 `1`. |
| `OH_MY_VLLM_GPU_UUID` | 一个完整的 GPU UUID. 此设置仅适用于数量为 `1` 的情况. |
| `OH_MY_VLLM_GPU_UUIDS` | 按顺序排列, 以逗号分隔的完整 GPU UUID 列表. 其长度必须等于设备数量. |
| `OH_MY_VLLM_GPU_EXCLUDE_INDICES` | 以逗号分隔的非负物理索引. 默认列表不包含任何索引. |
| `OH_MY_VLLM_RUN_ID` | 调用方提供的运行 ID. 值为空或未设置时生成新的 UUID. |

不要同时使用 `OH_MY_VLLM_GPU_UUID` 和 `OH_MY_VLLM_GPU_UUIDS`.
使用带小写十六进制数字和 `GPU-` 前缀的规范 GPU UUID.
不要在列表中使用空格或空元素.

排除设置优先于显式选择.
如果设备的索引被排除, 设备不存在或不是 B200, 显式列表将导致错误.
格式错误的设置和重复 UUID 也会在命令执行前导致错误.
显式指定的设备忙时会等待.

显式 UUID 列表设置 `CUDA_VISIBLE_DEVICES` 中的秩顺序.
自动选择使用递增的物理索引顺序.
包装脚本根据选择结果设置 `CUDA_VISIBLE_DEVICES`, 并替换之前的值.
加锁顺序不会改变秩顺序.

## 选择和所有权

[租约模块](../../development/serving/gpu.py) 通过 `nvidia-smi` 读取完整清单和计算进程列表.
只有已用显存不超过 64 MiB, 利用率为零且没有计算进程的 B200 设备才算空闲.
清单或进程输出格式错误时将导致错误.
不可用的测量值不算空闲.

每次尝试在加锁前选择完整的设备组.
模块按递增的 UUID 顺序获取非阻塞独占锁.
锁路径为 `/tmp/oh-my-vllm-${uuid}.lock`.
此路径与之前的单 GPU 包装脚本兼容.
锁文件必须是普通文件.
FIFO 锁路径会导致错误, 不会等待.

如果一个锁不可用, 模块会关闭本次尝试的所有描述符.
自动选择随后会尝试不包含该设备的设备组, 然后才进入下一次等待.
显式选择会等待其指定的设备组.
等待时不会持有部分设备组.

取得所有锁后, 模块会再次读取完整清单和进程列表.
已选设备变忙, 消失或发生变化时会释放设备组.
无效的显式选择会在释放后导致错误.

其他失败尝试会等待 10 秒再重试.
等待没有截止时间, 也不保证公平性.

包装脚本将所选 UUID 和运行 ID 输出到标准错误.
然后通过 `exec` 启动命令, 并继承锁描述符.
标准输入, 标准输出, 标准错误, 进程标识, 退出状态和命令信号均使用命令进程.
`exec` 前会重置 Python 忽略的管道信号和文件大小信号.

命令不存在时以状态 `127` 退出.
其他命令执行错误使用状态 `126`.
选择和清单错误使用状态 `2`.

每个锁的最后一个继承描述符关闭时, 操作系统会释放该锁.
父进程可以保持所有租约描述符打开, 直到全部 GPU 子进程停止.
这些子进程可以使用 `close_fds=True`.

如果子进程可能在父进程退出后继续运行, 它必须继承这些描述符.
如果父进程在子进程停止前关闭其描述符, 子进程也必须继承这些描述符.
如果所有权转移给子进程, 该子进程必须保留锁描述符, 直到其 GPU 工作进程停止.
在这些情况下, 当子进程使用 `close_fds=True` 启动 GPU 工作进程时, 应使用 `pass_fds`.

只要进程可能持有锁, 就不要删除锁文件.
包装脚本不会改变设备时钟, 也不会停止其他用户的进程.

协作式锁仅保护使用相同锁文件的命令.
其他进程可能在最后一次清单检查后启动 GPU 工作.
租约无法阻止该竞争.

## CUDA 身份检查

[设备模块](../../development/serving/device.py) 提供 `selected_uuids()`.
它接受 `CUDA_VISIBLE_DEVICES` 中一个或四个不同的完整 UUID.
如果提供了数量或 UUID 设置, 可见列表必须与这些设置一致.
它检查 `cuDeviceGetCount` 是否等于所选设备数量.
它通过 `cuDeviceGet` 映射每个逻辑序号, 并按所选顺序检查其 UUID.
它不会静默接受较小的可见设备集合.

`selected_uuid()` 仅接受一张所选 GPU.
因此, 现有单 GPU 使用方会拒绝四 GPU 选择.
CPU 检查使用受控驱动测试夹具.
它们不会在 GPU 上初始化 CUDA.
