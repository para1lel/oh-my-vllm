# DeepSeek V4.1 状态契约

## 权威来源和范围

本文档扩展版本为 1 的[源码契约](model.zh.md).
其中的 `LOCAL-V41` 身份使用该文档中的哈希值.
`LOCAL-V41:inference/model.py` 定义注意力和 DSpark 计算.
`LOCAL-V41:inference/engram.py` 定义 token 映射和哈希状态.
本契约区分本地数学计算与拟议的服务状态处理.

## 稀疏模式和源共享

层号从零开始.
层 0-1 和草稿层 40-42 仅使用滑动窗口注意力.
目标层 2-19 使用压缩率 2.
目标层 20-39 使用压缩率 1.
滑动窗口最多包含 128 个位置, 其中包含当前 token.

| 模式 | 层 | 全局状态 |
|---|---|---|
| Full | 2, 8, 14, 20 | 生成压缩 KV, 索引键和依赖查询的 top-k 索引 |
| Reindex | 24, 28, 32, 36 | 读取层 20 的 KV 和索引键, 然后计算新的 top-k 索引 |
| Reuse | 其他压缩层 | 读取最近的源的 KV, 键和 top-k 索引 |

Full 是稀疏源模式的名称, 不是稠密全上下文注意力.
打包主 KV 的每个压缩行使用 `512/2+512/16=288` 字节.
打包索引键的每个压缩行使用 `128/2+128/32=68` 字节.
因此, 四个源存储在复制和分配取整之前每 token 使用 `(288+68)*(3/2+1)=890` 字节.
这不包含窗口, 未完成组, 推测状态和工作区.

KV 和索引键的源范围为 2-7, 8-13, 14-19 和 20-39.
Top-k 源范围在 24, 28, 32 和 36 处分割最后一个范围.
对于相同查询行, 源在消费者之前运行.
参考实现通过 `SharedAttentionRuntime` 传递共享张量.
这些进程全局引用不是持久请求身份.
服务必须显式绑定源身份, 查询行布局, 位置和请求所有权.

本地 prefill 路径从位置 0 开始.
其非零位置路径每个序列接收一个 token.
它不提供任意分块继续计算或多行目标验证.
新的分块算子必须跨分块边界传递未完成组和因果可见性.
在非零位置复用初始 prefill 路径会改变数学计算.

每层仍然生成自己的滑动窗口 KV.
源共享适用于全局压缩 KV 和索引状态, 不适用于本地滑动窗口 KV.
压缩率为 2 的压缩器使用 FP32 投影值和逐通道门控分数.

对于每个完整 token 对, 对两个 token 分数做 softmax 得到逐通道池化权重.
池化值在 RMS 归一化之前返回 BF16.
压缩率为 1 时, 使用 BF16 投影和 RMS 归一化, 不做池化.
未完成的压缩率为 2 的组不发布全局行.

压缩行 `j` 使用 RoPE 位置 `j*ratio`, 即该组第一个 token 的位置.
索引键使用主 KV 的 RoPE 和 FP4 量化之前的归一化潜向量.
索引投影, 归一化, RoPE 和 FP4 量化在该潜向量被覆盖之前运行.
随后, 主 KV 接受其自身的 RoPE 和缓存量化.
在查询位置 `p`, 仅 `floor((p+1)/ratio)` 个完整组可见.

索引器有 32 个头, 每头宽度为 128.
它将旋转后的查询和键量化为 FP4.
其分数为 `ReLU(q_h dot k)` 乘以有符号投影头权重后的总和.

头权重因子为 `1/sqrt(128*32)`.
它最多选择 512 个位置, 然后按位置排序其索引.
无效项使用 `-1`.
本地没有显式的 top-k 同分决策规则.

层 20 为后续 reindex 层构建候选池.
每个块包含八个压缩位置.
块分数是最大位置分数.
最新可达块获得无限分数, 以强制纳入候选池.

候选池最多包含 2048 个可达块.
后续 reindex 层仅对该池应用自身分数.
本地参考实现在掩码之前计算稠密索引分数.
它不能证明存在适用于百万 token prefill 的有界内存稀疏实现.

注意力将本地窗口项与选中的全局项拼接.
即使其源 token 区间重叠, 它们仍然是不同缓存项.
对于每个头, 数学输出为 `sum(exp(q dot k/sqrt(512))*k)/(exp(sink)+sum(exp(q dot k/sqrt(512))))`.
Sink 向分母贡献质量, 但不提供 value.
本地内核使用 FP32 softmax 统计量, 并使用 BF16 指数操作数累加 value.
所有项均无效的行产生零输出.

## Engram 映射和位置

Engram 在目标层 1 和 14 之前运行.
它对 2-, 3-, 4-gram 做哈希, 每个长度有八个头.
每次查表有 256 个通道, 因此每个 token 在每个 Engram 层获取 24 行.
压缩词表大小必须等于 99092.

`build_compressed_token_map` 按升序访问原始 token ID.
它解码每个 token, 不跳过特殊 token.
归一化按源码顺序应用 NFKC, NFD, 去重音, 小写, 空白折叠和 strip.
私用区哨兵字符保护单个空格, 使其不被 strip 删除.

空归一化字符串回退为解码文本.
包含 Unicode 替换字符的 token 使用其原始 token 写法.
每个压缩 ID 按首次出现分配.
因此, 分词器库和归一化版本是身份输入.

哈希乘数使用 NumPy `default_rng(10007*layer_id)`.
源码抽取四个 signed-int64 值, 然后应用 `2*v+1`.
不含端点的上界为 `(INT64_MAX//99092)//2`.

连续回看位置的乘积用 XOR 组合, 而不是加法.
每个 n-gram/头使用不同的质数模数和累积表偏移.
每个 n-gram 范围从大于 15999999 的数开始搜索质数.
已用质数集合跨全部范围和 Engram 层共享.

位置是绝对语言模型 token 偏移.
回看到达序列起点或无效图像片段 token 时停止.
不可用 token 使用 PAD token 2 的压缩映射.
图像 token 阻断自身和所有更早的回看位置.

它不接收 Engram 贡献.
后续文本可以使用自身的文本后缀, 但不能跨越该图像边界做哈希.
参考实现按绝对位置缓存压缩 ID.
继续计算只需最后三个 ID, 其无效标记和已接受长度.
这一缩减来自最大 4-gram 回看范围, 不是注意力重放假设.

查表行在 Engram 投影之前反量化为 BF16.
投影提供四个键和一个共享 value, 宽度为 5120.
门控使用逐副本 RMS 归一化的键/残差点积, 以及查询/键归一化权重的乘积.
它应用绝对值下限为 `1e-6` 的有符号平方根, 然后应用 sigmoid.
门控 value 在目标块之前加到各残差副本.
有界设备暂存不得改变行 ID, 缩放值或加法位置.

## DSpark 隐藏状态和提议

本地配置有三个草稿层, 块大小为 5.
每个草稿层有 128 个路由专家, 选中三个专家.
目标特征拼接层输入 37, 38 和 39 在四个残差副本上的均值.
这些是注意力之前的块输入, 不是层输出或最终归一化隐藏状态.
`main_proj` 将 15360 个通道映射为 5120, 然后做 RMS 归一化.

草稿 prefill 仅初始化各草稿层的主 token 窗口 KV.
它不为提示词提议执行草稿注意力/FFN.
Decode 在绝对位置 `p` 消费一个目标特征行.
五个草稿输入行的首项是目标采样 token, 后续项为噪声 token 128799.

其注意力位置为 `p+1` 到 `p+5`.
每个草稿行可见已接受的主 token 窗口和全部五个草稿 KV 行.
草稿块是双向的, 不是五个因果目标步骤.
草稿嵌入和词表头使用目标模型的权重.

合并和草稿归一化之后, 词表头提供五个基础 logit 行.
秩为 256 的 Markov 头根据前一个采样 token 添加词表偏置.
因此, 尽管草稿注意力并行, 提议分布仍然顺序依赖此前采样的提议.

`forward_head` 返回六个 ID: 给定的目标 token 和五个提议.
其返回的 logits 包含这些 Markov 偏置.
置信度投影将未归一化的合并隐藏状态与前一个 token 的 Markov 嵌入拼接.
本地结果是原始标量, 不是 sigmoid 概率.

DeepInfer 的[置信度内核](https://github.com/deepseek-ai/DeepInfer/blob/9bd9cf243fc53ef9afbf8f04d391d989117d6ab9/deepinfer/model_executor/layers/tilelang_ops/cuda/dflash.py) 先除以温度, 截断到 `[-60,60]`, 然后应用 sigmoid.
其[草稿路径](https://github.com/deepseek-ai/DeepInfer/blob/9bd9cf243fc53ef9afbf8f04d391d989117d6ab9/deepinfer/model_executor/models/mtp/dflash.py) 为验证存储提议概率.
本地 forward 没有这些操作.
置信度校准和验证预算选择需有单独获批的契约.
置信度改变验证长度, 不改变接受率公式.

本地采样器使用温度 softmax 和指数竞赛采样, 或在温度为 0 时使用 argmax.
它不实现服务惩罚, 语法掩码, top-k/top-p, 拒绝校正或 RNG 分配.
对于随机服务验证, `q_i` 必须是生成提议 `y_i` 的完整约束分布.
目标分布 `p_i` 使用相同的已接受前缀和约束.
在后续验证行, 该前缀包含当前行之前的提议 token.
这些行的语法和惩罚更新使用私有推测状态.

精确拒绝采样按 `min(1,p_i(y_i)/q_i(y_i))` 接受.
首次拒绝时, 校正分布正比于 `max(p_i-q_i,0)`.
全部接受的前缀允许再做一次目标采样.
因此, 五个草稿最多可使用六个目标验证行.
这些是服务要求, 不表示本地循环已实现它们.

DeepInfer 的[采样器](https://github.com/deepseek-ai/DeepInfer/blob/9bd9cf243fc53ef9afbf8f04d391d989117d6ab9/deepinfer/model_executor/layers/tilelang_ops/cuda/fused_sample.py) 在校正期间减去 `exp(draft_logprob-DRAFT_PROB_PENALTY)`.
不得将这一调整用作前述精确公式.
实现之前, 冻结概率存储, RNG 流和绝对采样位置.
被拒绝的行不得推进已接受的语法, 惩罚, token 历史或逻辑输出位置.
接受和校正随机抽样使用与输出 token 抽样分开的 RNG 分配.
本地源码没有定义这些服务 RNG 流.

## 已接受状态和恢复

缓存长度计数已处理的输入 token, 而不是采样已经发出的全部 token.
采样得到的下一个 token 可以已被接受, 但尚未写入目标 KV.
将该待处理 token 与已处理前缀长度和目标特征位置分开保存.
拒绝之后, 校正 token 必须经过目标计算, 才能使用其 KV 或目标特征.

| 状态组 | 已接受内容 |
|---|---|
| 目标窗口 | 逐层 128 位置 KV, 绝对长度和环形槽位映射 |
| 全局源 | 四个压缩 KV 存储, 四个索引键存储和有效长度 |
| 未完成压缩器 | 未完成的压缩率为 2 的组的 FP32 值和门控分数 |
| 稀疏选择 | 源身份, 查询位置, 候选项和 top-k 行布局 |
| Engram | 最后三个压缩 ID, 无效标记和已接受长度 |
| DSpark | 三个主 token 窗口, 目标特征, 提议分布和验证位置 |
| 采样 | 已接受 token, 语法/惩罚历史, 停止状态和 RNG 分配 |

若在使用前重新计算, 候选掩码和 top-k 索引可以是临时状态.
它们不能来自被拒绝的行或其他请求.
将推测写入与已接受状态分开.

验证之前, 使用影子槽位或保存将被覆盖的环形项.
任意位置发生拒绝之后, 恢复有效长度和未完成压缩器内容.
仅截断 token 数组不能撤销环形覆盖或已完成的推测压缩组.
共享源回滚必须为全部消费者和 rank 选择一个一致状态.

在拥有完整已接受状态且算术契约相同时, 精确继续计算是可行的.
本次源码阅读不能证明不同归约布局间输出逐字节相同.
前缀身份必须绑定权重, 分词器映射, 媒体, 绝对位置, 格式和并行布局.
主机卸载必须存储足以支持这种继续计算的状态.

DeepInfer 的[重放说明](https://github.com/deepseek-ai/DeepInfer/blob/9bd9cf243fc53ef9afbf8f04d391d989117d6ab9/doc/inference_deployment_qa.md) 将截断的 128-token SWA 重放称为近似方法.
本地依赖层的 SWA 输入会通过更深层传播依赖.
因此, 单个 128-token 尾部不能作为精确恢复证明.
除非足够的重放构造已获批准, 否则保留完整的已接受窗口.
这里没有批准固定重放长度.
