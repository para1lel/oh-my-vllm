# Qwen HTTP 结果

## 范围和方法

本报告包含最新完成的 Qwen HTTP 矩阵.
下方源码身份标识本次测量的实现.
Qwen 保留其单 worker 执行路径, coordinator, wire 字段和七个 native 模块.

这些测量不执行类型化四 rank 模型路径.
它们不测量 DeepSeek, 四 GPU 执行, DSpark 或百万 token 容量.
日期为 Asia/Shanghai 时区的 2026-10-24.
[Qwen 流程](../performance.zh.md) 给出 24 个 HTTP 配置和 `serving-tools-v1` 工作负载.

每行使用一张 B200, 并发 HTTP 请求, 以及每个请求指定且未缓存的输入/输出长度.
服务最多有四个活跃请求, 每步预算为 32768 tokens, 上下文限制为 262144 tokens.
采样使用 temperature 1.0, top-k 20, top-p 0.95, presence penalty 0.5, 重复保护和客户端序号种子.
推理模式关闭. 工具选择为 auto.
必选工具检查和短预热请求在测量用例之前执行.

HTTP 秒数包含请求线程创建, 提交, 准备, 排队, 模型执行和完整 JSON 响应读取.
计时不包含初始化或 trace 分析.
输入/s 和输出/s 等于 batch token 总量除以同一个完整 HTTP 秒数.
TTFT 是服务端首 token 时间的均值, 单位为毫秒, 并非客户端流式延迟.
接受/提议计数来自被测请求, 且服务日志与执行 trace 一致.
普通解码没有草稿接受率.

## Prefill

32768-token 预算适用于整个步骤, 而非每个请求.
请求数翻倍不会让每步投影的行数翻倍.
调度器和 worker 使用 784-token 块, 每个 batch 最多允许一个非整块 prefill 请求.

当一个 batch 中有请求包含至少 512 个 query tokens 时, FA 使用 ring kernel.
109 个被测 shape 中有 45 个改变了 kernel 选择. 这 45 个用例的 `median_ms` 值均降低.
表格使用每请求 784 个 query tokens, 262144 个 context tokens 时的完整 FA `median_ms` 值.
每个用例使用 30 个样本, 每个样本至少包含 20 ms 的 GPU 工作.
基线为 `d24fef8` 的原 FA 实现.

| Batch | 修改前, ms | 修改后, ms |
|---|---:|---:|
| 1 | 4.9425 | 4.9870 |
| 2 | 12.2000 | 9.9796 |
| 4 | 24.5150 | 19.9376 |

产物 `fa-extended-baseline.json` 和 `fa-extended-candidate.json` 绑定 native 身份及全部被测 shape.
它们保存在仓库外的 `qwen-prefill-scaling-20261023` 产物集中.
数值门槛和算子延迟门槛没有改变.

Host KV 内存池在 Ready 前预留 pinned 容量.
这将 pinned host-cache 分配从请求处理阶段移到启动阶段.
前缀存储和必需的请求卸载保持启用.
传输仍会占用缓存容量和内存带宽.
[Host 缓存指南](../kv-offload.zh.md)给出启动内存和失败条件.
