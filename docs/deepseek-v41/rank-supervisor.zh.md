# Rank 进程所有权

## 范围

[组客户端](../../crates/zmq-worker/src/rank_client.rs) 将 [rank 检查器](rank-control.zh.md) 连接到所拥有的 worker 进程.
它使用与 Qwen 客户端相同的 Rust 进程组和 IPC 清理机制.
Qwen 客户端使用同一个提取出的[生命周期模块](../../crates/zmq-worker/src/client/lifecycle.rs).
其协议和模型执行保持不变.

组客户端目前未连接到服务调度器.
`tests/rank_peer.py` 中的 CPU 对端是测试程序, 而非模型适配器.
此测试程序不执行 DeepSeek 模型, 原生集合通信或分布式 CUDA Graph.
[阶段计划](plan.zh.md) 规定这些集成门槛.

## 启动与传输

调用方提供 epoch, 模型描述符, 有序 GPU UUID, 逻辑容量限制和 worker 命令.
调用方还提供已可用的 IPC 目录, 以及为正值的启动和步骤超时.
模型策略必须在服务集成前选择该命令.
此接口不检测模型家族, 也不提供相应批准.

构造函数在启动 worker 前验证组契约.
每个 rank 获得独立的 IPC 端点和 DEALER 连接.
启动前 IPC 路径必须不存在.
客户端不会为启动 worker 而移除或替换条目.
调用方必须拥有该目录, 并阻止其他进程修改其中的条目.
主机路径应放在被忽略的本地配置中.

每个 worker 在不同且由调用方拥有的进程组中运行.
在 Linux 上, worker 使用与 Qwen worker 相同的父进程退出信号设置.
有序 UUID 列表成为每个 worker 的 `CUDA_VISIBLE_DEVICES`.
逻辑 rank 是命令参数.
原生 worker 必须在报告就绪前通过 CUDA 驱动验证设备标识.
[GPU 包装器](gpu-groups.zh.md) 拥有设备选择和协作锁.

此客户端不管理这些锁.

每个回复携带来自连接的来源 rank 进入有界收件队列.
回复必须包含一个至多 1 MiB 的 msgpack 帧.
就绪和完成消息通过 rank 检查器.
启动对进程启动, 初始化发送和就绪使用同一个组截止时间.
收件队列为空时, 客户端监测进程退出并检查截止时间.
启动发送重试不会延长该截止时间.

## 状态生命周期

`execute` 接收步骤计划和所拥有的[状态事务](state-arena.zh.md).
派发前, 它们的 epoch, 步骤, 请求和事务 ID 必须与调度一致.
客户端在 rank 执行期间保留这些事务.
取消等待 future 不会释放它们, 也不会启动后续步骤.

所有 rank 都必须提供正确完成元数据, 包括本地调度为零行时.
只有此时, 客户端才返回带有完成记录和事务的 `CompletedStorage`.
调用方必须验证模型输出并选择已接受状态.
此返回值不发布前缀, 也不验证物理张量布局.

## 失败与关闭

worker 退出, worker 错误, 无效回复, 传输错误或截止时间到期会使组操作失败.
客户端在返回操作失败前停止所拥有的全部进程组.
`close` 也会停止这些组.
此底层关闭使用进程终止, 而非优雅的模型关闭消息交换.

一个清理所有者保留所有子进程和待定事务.
它向全部所拥有的组发送终止信号, 然后等待它们.
它等待 worker 及其进程组后代停止后才释放事务.
清理线程无法启动时, 调用线程执行相同清理.
清理不能仅因超时或取消而释放存储.

关闭会中止连接读取器, 且只移除与记录的文件标识相符的 IPC 条目.
如果关闭等待 future 被取消, 不同的清理任务使这些操作继续执行.
后续关闭调用等待同一个完成来源.
关闭为后续等待保留相同结果, 清理错误后也是如此.

丢弃客户端也会启动所拥有进程的清理, 并保留待定事务直到清理完成.
客户端句柄消失后, 后台清理可以继续执行.
为获得前一组已停止的证据, 在替换前调用 `close`.
等待其结果.
客户端不会重启失败的组, 也不会恢复其活跃请求.

## 检查与限制

CPU 进程测试使用四个 Python 对端, 以及 DEALER 连接和 msgpack 消息.
它们覆盖复制调度, 请求分区, 零行 rank, 启动错误, 执行错误, 挂起的 worker 和取消.
它们还测试进程组后代, IPC 移除, 租约释放, 以及一个无关但由测试拥有的进程.
关闭等待检查使用清理完成通道, 并在完成前取消等待.

这些检查不提供 GPU 数值, 集合通信顺序, 原生内存, 吞吐量或容量证据.
类型化调度器集成, 优雅服务关闭和原生通信是后续阶段 2 工作.

scripts/with-env.sh cargo test -p oh-my-vllm-zmq-worker --test rank_client
