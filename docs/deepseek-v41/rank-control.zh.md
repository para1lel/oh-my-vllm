# Rank 组验证

## 范围

[组检查器](../../crates/zmq-worker/src/group.rs) 为阶段 2 验证 rank 就绪和完成元数据.
其[消息](../../crates/zmq-worker/src/group/protocol.rs) 使用组协议版本 1.
现有 Qwen worker 协议和客户端目前不使用此检查器.
此模块不启动进程, 不执行集合通信, 不验证模型输出, 也不发布已接受前缀.
[阶段计划](plan.zh.md) 中的这些集成步骤仍然必要.

## 就绪

调用方提供 epoch, 预期模型描述符, 有序 GPU UUID, 容量限制和启动截止时间.
epoch 必须为正数.
GPU UUID 必须互不相同, 并使用规范的小写格式.
列表位置标识逻辑 rank, 而非物理 GPU 索引.

每个回复绑定其协议版本, epoch, 逻辑 rank, 设备 UUID 和模型描述符.
调用方从连接而非回复中提供来源 rank.
检查器比较这两个 rank 标识.

除已分配缓存容量外, 所有描述符字段必须与预期描述符一致.
每个已分配容量必须至少达到请求的最小值.
每个池必须为其空槽和队列哨兵留出空间.
共享视图必须与其生产者具有相同的种类, 块单位, 格式和容量.

完整容量预算计算各 rank 拥有的逻辑槽, 包括空槽.
它不重复计算共享视图.
它不是 GPU 字节预算.
在每个 rank 都提供有效就绪信息之前, 容量结果不可用.
结果保留每个 rank 的容量, 以及每个组的最小公共容量.
DEP 调度还必须保留每个请求的所属 rank.

## 组步骤

步骤提供递增的步骤 ID, 以及唯一的请求 ID 和事务 ID.
事务 ID 必须大于此前步骤的所有事务 ID.
计划还提供请求归属, 行数, prefill 标志, 集合通信计划 SHA256 和集合通信次数.
配置的请求数和行数限制在派发前生效.
无效的本地计划不启动步骤, 也不使已就绪的组失败.

TP 和 TEP 向每个 rank 发送相同的请求工作.
rank 零拥有其请求输出.
DEP 只向请求所属 rank 发送请求工作.

每个 rank 都收到调度.
此规则也适用于零行的 rank.
如果任何请求包含 prefill, 则整个组使用 Eager 执行.
如果没有请求包含 prefill, 则整个组使用 CUDA Graph 执行.

每个结果必须指明当前 epoch, 步骤, rank 和集合通信计划.
其事务集合必须与调度的本地事务集合相同.
它必须报告完整的集合通信次数以及设备工作已完成.
零行 rank 也必须报告完成.

只有全部 rank 都报告有效完成后, 检查器才返回一个 `CompletedStep`.
此值的字段为私有, 且没有克隆或反序列化实现.
它记录 rank 一致性, 而非已接受的模型状态或逻辑存储所有权.

## 失败与资源所有权

无效的就绪信息或结果使组失败.
这包括过期标识, 重复项, 缺失事务, 不同的集合通信计划, 以及未完成的设备工作.
rank 失败也会使组失败.
启动截止时间或步骤截止时间到期也会使组失败.
失败的组不能接受后续结果或启动另一个步骤.
检查器不返回部分完成值.

监督器必须在等待时检查截止时间, 包括没有消息到达时.
检查器不包含定时器任务.
子进程退出或传输操作失败时, 监督器必须使检查器失败.
检查器信任所拥有 worker 的完成元数据.
原生 worker 必须等待设备和传输完成后才能发送该元数据.
仅回传摘要不能证明集合通信顺序或设备执行正确性.

检查器不拥有状态租约, CUDA 资源或子进程.
监督器必须保留这些资源, 直到全部设备工作完成或所有旧 worker 停止.
取消或检查器失败不足以授权释放这些资源.
发布前, 调度器必须验证模型输出, 并将完成信息绑定到自己的待定事务.
[状态 arena](state-arena.zh.md) 提供逻辑租约, 而非该发布操作.

## 检查

CPU 测试为就绪, 容量限制, 请求分配, 零行 rank, 过期结果, 重复结果和截止时间提供证据.
它们包含 msgpack 完成消息.
它们不证明进程清理, 原生集合通信执行, CUDA Graph 安全性, 数值精度或模型容量.

```bash
scripts/with-env.sh cargo test -p oh-my-vllm-zmq-worker --test group
```
