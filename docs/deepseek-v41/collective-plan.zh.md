# 集合通信计划

## 范围

[Rust 计划](../../crates/zmq-worker/src/group/collectives.rs) 定义有序通信契约.
[Python 读取器](../../python/oh_my_vllm/operators/runtime/distributed.py) 在不导入 GPU 模块的情况下验证相同契约.
这些模块规定通信, 而非模型计算或已接受状态.
它们不证明原生执行或 CUDA Graph 安全性.

计划包含版本, world size 和有序操作.
版本 1 允许 world size 为 1 或 4, 且最多包含 4096 个操作.
空操作列表有效.
world size 必须与调用方的组拓扑一致.
未知字段, 操作和数据类型无效.

## 操作与缓冲区

每个操作在每个 rank 上使用一个输入缓冲区和独立的输出缓冲区.
缓冲区包含指定数据类型的连续元素.
原生执行必须在入队前拒绝存储重叠, 以及错误的设备, 形状, 类型或步长.
计划定义元素计数, 而非字节偏移或原始设备地址.

| 操作 | count 的含义 | 每个 rank 的输入元素数 | 每个 rank 的输出元素数 |
|---|---|---:|---:|
| `all_reduce` | 使用 sum 归约的元素数 | count | count |
| `all_gather` | 每个 rank 提供的元素数 | count | count 乘以 world size |
| `reduce_scatter` | 每个 rank 在 sum 后接收的元素数 | count 乘以 world size | count |
| `route` | 从源到目标的方形计数矩阵 | 源行之和 | 目标列之和 |

Route 输入分段使用目标 rank 顺序.
Route 输出分段使用源 rank 顺序.
矩阵包含自身路由和零计数路由.
每个 rank 收到相同矩阵, 没有已调度请求时也是如此.
原生实现必须使用匹配的发送和接收计数.

数据类型为 `f32`, `bf16`, `f16`, `i32`, `i64` 和 `u8`.
计数为无符号 64 位整数.
每个缓冲区的总字节数必须能存入有符号 64 位整数.
验证在派发前检查乘法以及行和列之和.
Python 拒绝布尔值, 负值和非整数计数.
Python 读取器生成已验证操作的不可变副本.

## 规范标识

对于所有 msgpack 映射顺序, SHA256 使用以下字节序列:

1. ASCII 域 `oh-my-vllm/collectives/v1`, 后跟一个零字节.
2. 版本, world size 和操作次数, 各为一个无符号 32 位小端整数.
3. 按操作顺序排列的每个操作标签字节和数据类型标签字节.
4. 该操作的计数, 为无符号 64 位小端整数; 或按行主序排列的全部 route 计数.

操作标签为: `all_reduce` 对应 0, `all_gather` 对应 1, `reduce_scatter` 对应 2, `route` 对应 3.
数据类型标签为: `f32` 对应 0, `bf16` 对应 1, `f16` 对应 2, `i32` 对应 3, `i64` 对应 4, `u8` 对应 5.

[rank 检查器](rank-control.zh.md) 从已验证计划计算摘要和操作次数.
一个 route 操作计为一个操作, 而非其各个原生发送和接收的数量.
worker 必须独立验证计划, 并在原生执行前比较两个计算值.
只有全部计划操作和设备工作完成后, 它才能报告完成.

## Graph 集成

适配器必须在捕获前选择固定填充计数.
数据依赖的路由不能在重放期间更改计划.
适配器必须提供填充值和有效行元数据.
graph 键必须绑定计划标识和拓扑.
其所有者必须在捕获, 重放和完成期间保持通信器及缓冲区地址有效.
Eager 模式和 CUDA Graph 模式必须执行相同的有序原生操作.

## 检查

Rust 和 Python 检查使用一个包含全部四类操作及不均衡路由的固定计划.
fixture 提供固定摘要及各 rank 的缓冲区计数.
检查拒绝错误拓扑, 溢出, 不支持的字段和无效类型.
它们也检查顺序, 类型和路由的变化会改变摘要.
这些 CPU 检查不提供模型数值或 GPU 性能证据.
