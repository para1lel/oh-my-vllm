# Nightly Qwen 类型化执行回归

## 范围和方法

这些测量检查增加类型化四 rank 执行接口后的 Qwen.
Qwen 保留其单 worker 执行路径, coordinator, wire 字段和七个 native 模块.

这些测量不执行类型化四 rank 模型路径.
它们不测量 DeepSeek, 四 GPU 执行, DSpark 或百万 token 容量.
日期为 Asia/Shanghai 时区的 2026-10-23.
[Qwen 流程](../performance.zh.md) 定义 24 个 HTTP 配置和 `serving-tools-v1` 工作负载.

每行使用一张 B200, 并发 HTTP 请求, 以及每个请求指定且未缓存的输入/输出长度.
服务最多有四个活跃请求, 每步预算为 32768 tokens, 上下文限制为 262144 tokens.
采样使用 temperature 1.0, top-k 20, top-p 0.95, presence penalty 0.5, 重复保护和客户端序号种子.
推理模式关闭. 工具选择为 auto.
必选工具检查和短预热请求在测量用例之前执行.

HTTP 秒数包含请求线程创建, 提交, 准备, 排队, 模型执行和完整 JSON 响应读取.
计时不包含初始化或 trace 分析.
输入/s 和输出/s 等于 batch token 总量除以同一个完整 HTTP 秒数.
TTFT 是服务端首 token 时间的均值, 单位为毫秒, 并非客户端流式延迟.
接受/提议计数来自被测请求, 且服务日志与执行 trace 一致.
普通解码没有草稿接受率.

## 失败和内存

全部 24 个配置完成, 共 56 个被测请求, 无被测请求失败.
基准检查了完整输出长度, 输入缓存 token 为零, 工具帧和运行时身份.
本会话的 CPU 参考任务在测量期间不执行.
基准结束后, 它继续计算.

外部身份文件记录所选设备的 UUID.

请求超时为 7200 秒. Worker-step 超时为 600 秒. 关闭宽限期为 35 秒.
