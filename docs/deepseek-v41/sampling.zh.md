# DeepSeek DSpark 采样约定

## 范围

此版本 1 约定定义项目的服务行为, 而不是本地检查点的生成循环.
[状态约定](state.zh.md) 定义预测器数学和持久状态.
[CPU 参考程序](../../development/model/deepseek_v41/sampling_reference.py) 定义精确拒绝采样和独立随机抽样.
推理运行时不使用此参考程序.
Qwen 保留现有采样和 RNG 行为.

## 位置和待处理 token

位置是从零开始的语言模型 token 位置.
已处理长度统计已形成状态的目标模型输入.
待处理 token 已被接受并输出, 但其目标模型计算尚未完成.
它的位置等于已处理长度.
生成步骤之间最多存在一个这样的 token.

对于长度为 `N>=2` 的提示词, 目标模型 prefill 计算位置 `0..N-1`, 并在位置 `N` 采样待处理 token `t`.
预测器播种使用位置 `0..N-2` 的目标特征.
提案调用追加 `p=N-1` 处的边界特征, 并接收 `t` 作为第一个输入 token.
因此, 预测器主状态长度变为 `N`.

五行草稿注意力使用位置 `N..N+4`.
它们的 logits 预测输出位置 `N+1..N+5` 上的提案 `y1..y5`.
注意力行的位置不是其预测 token 的位置.
每个 Markov 偏置使用前一个 token: 先是 `t`, 然后是 `y1..y4`.

[FP64 预测器](../../development/model/deepseek_v41/reference_dspark.py) 将 `append_main`, `project_features` 和 `forward` 分开.
它不根据张量形状推断服务位置.
它的主窗口更新不执行预测器 FFN.
播种分块仅保留有界窗口及绝对位置.

对于只有一个 token 的提示词, 先使用普通目标模型解码.
仅在边界特征满足 `p>0` 时开始提案.
接近上下文上限时, 如果五个预测器注意力位置不能全部容纳, 则使用普通解码.
不要缩短双向预测器块后声称数学计算相同.

## 验证和状态提交

令 `L` 为验证前待处理 token 的位置.
选择零到五之间的验证数量 `K`.
目标模型计算在位置 `L..L+K` 消费 `[t,y1,...,yK]`.
目标行 `i` 预测位置 `L+i+1` 的 token.
它使用包含此前提案 token 的私有语法和惩罚历史.

如果 `a` 个草稿通过接受检查, 则发布这些草稿以及一个修正或奖励 token.
目标模型的已处理长度变为 `L+1+a`.
最后发布的 token 仍在该位置等待处理.
参考程序的 `processed_rows` 是 `1+a`, 而不是已接受草稿的数量.
不要使用被拒绝提案的特征来处理修正 token.

下一次提案前, 将位置 `L` 到 `L+a-1` 的已接受目标特征追加到预测器主窗口.
保留位置 `L+a` 的特征, 供该次提案追加边界.
当 `a=0` 时, 中间追加为空.
被拒绝的目标行和预测器提案行绝不进入已接受的主窗口.

如果停止条件提前结束输出, 则丢弃后续输出和状态.
绝不提交超出已接受 token 历史的目标状态.
发布前, 每个状态组必须选择相同的已接受前缀.
环形槽位, 压缩器未满组和来源身份遵循[恢复规则](state.zh.md#已接受状态和恢复).

令 `R` 统计待处理 token 之后仍允许输出的 token 数量.
它包含总上下文限制.
如果 `R=0`, 则无需验证, 直接结束.
否则使用 `K<=min(5,R-1)`, 确保始终为修正或奖励 token 预留空间.
停止条件可以进一步减少发布量.

## 概率规则

对目标和提案 logits 应用相同的请求设置, 语法, 惩罚和停止 token 掩码.
这些变换使用各自的已接受前缀或私有提案前缀.
存储实际生成每个提案 token 的完整分布.
不要根据后续 logits 重建它, 也不要只存储被采样 token 的概率.
Markov 偏置先于这些变换.

数学参考使用有限, 非负且总和为一的 FP64 概率行.
它允许总和误差最多为 `1e-12`, 然后以 FP64 对行进行归一化.
实现必须另外对照此参考验证概率舍入.
本文档不设定概率舍入容差或模型 logits 限制.

对于提案 `y_i`, 当 `u_i < min(1,p_i(y_i)/q_i(y_i))` 时接受.
如果被采样提案满足 `q_i(y_i)=0`, 则输入无效.
目标概率为零时, 即使均匀随机数为零也必须拒绝.
首次拒绝时, 从归一化后的 `max(p_i-q_i,0)` 采样.
不要减去缩小后的提案概率, 也不要增加修正惩罚.
拒绝时剩余概率质量为零属于错误, 不能因此改用目标分布.

如果全部 `K` 个草稿通过, 则从目标行 `K` 采样奖励 token.
当 `K=0` 时, 这就是普通目标采样.
分类采样使用 token 升序 CDF 和 `[0,1)` 范围内的均匀随机数.
不能选择零概率质量的 token.
贪心解码仅接受与目标 argmax 相同的 token, 并输出首次不匹配的 token 或最终奖励 token.
argmax 完全相同时选择较小的 token ID.

## RNG 分配

DeepSeek 使用 Philox4x32-10, 以无符号 64 位请求种子的两个字作为密钥.
计数器的字为 `[position_low32,position_high32,cycle,stream]`.
位置指被采样的输出 token, 而不是目标输入行.
请求内的无符号 32 位 cycle 统计生成决策.
cycle 0 是 prefill 后的第一次目标采样.
下一次提案及其验证共用 cycle 1, 然后是 cycle 2, 以此类推.

| 流 | ID | 用途 |
|---|---|---|
| Target | 0 | 普通目标采样和初始 prefill 输出 |
| Proposal | 1 | 每个提案输出位置的一次分类采样 |
| Accept | 2 | 每个已验证提案位置的一次接受抽样 |
| Correction | 3 | 首个拒绝位置的一次分类采样 |
| Bonus | 4 | 非空前缀全部接受后的一次目标抽样 |

使用前两个结果字计算 `((word0<<21) | (word1>>11))*2^-53`.
批内索引, rank ID, worker epoch 和执行顺序均不进入此地址.
未使用的抽样不引发可变计数器更新.
一次完整决策使 cycle 增加一, 与接受长度无关.
新提案块始终使用新的 cycle, 即使其位置与已丢弃提案重叠.
检查计数器溢出, 不允许回绕.

Graph 录制不消耗 RNG 状态.
所有 rank 使用请求所有者的地址, 而不是各自单独抽样.
请求失败会中止事务.
它不会发布部分决策.
此约定提供确定性地址, 不保证普通解码和推测解码产生相同 token 路径.

## 置信度调度

先验证固定长度验证路径.
默认验证上限为五.
输出和上下文限制可以降低它.
原始置信度不是接受概率.
初始测量的固定五草稿路径不使用校准后的置信度阈值.

后续可选策略可以用 `sigmoid(clamp(raw/Tc,-60,60))` 选择较短前缀, 其中 `Tc>0`.
它在首个低于配置阈值的分数之前停止.
阈值和 `Tc` 必须包含在测量身份中.
行 `i` 的分数仅依赖主特征和提案 `i` 之前的 token.

不要使用行 `i` 的已选 token 来决定是否验证该行.
不要使用后续提案 token 或接受随机数来作出该选择.
这种选择可能使采样产生偏差.
置信度绝不改变 `p`, `q` 或接受公式.

## 验证边界

少量 CPU 检查覆盖五个拒绝位置, 全部接受, 零草稿, 剩余质量, 零概率, 贪心并列和 Philox 已知向量.
它们不能证明运行时语法, 停止, 分布式回滚或 RNG 集成正确.
阶段 6 必须验证这些路径后, 才能接受 DSpark 服务支持.
