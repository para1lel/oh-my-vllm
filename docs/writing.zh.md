# 文档写作规则

项目自有英文 Markdown 遵循 [ASD-STE100 Issue9](https://www.asd-ste100.org/assets/files/ASD-STE100_ISSUE9.pdf), 发布日期 2025-01-15.
使用其写作规则及词典批准的词义, 词性和词形.
必要技术名词和动词使用 [项目术语表](glossary.zh.md).
标准允许技术术语; 此表不为通用同义词提供授权.

## 英文流程

批准词使用批准的词义和词性.
技术术语只用于定义的项目含义.
同一概念保持同一术语.
优先使用简短, 直接, 主语已知的主动陈述.
描述文本只有施事者未知时才使用被动语态.

动词使用 infinitive, imperative, simple present, simple past 或 simple future.
Participle 只作允许的 modifier, 不使用 progressive 或 perfect tense.
`-ing` 技术名词可以命名定义的操作.
代码语法, 命令, 标识符, 精确消息, 许可证和源码片段保持不变.

操作句至多 20 词, 描述句或 note 至多 25 词.
描述段落围绕一个主题, 至多 6 句.
独立动作或并列合同使用列表.
列表引导和每个项目分别计算句长.
正文不使用分号.
数量比较使用批准措辞, 例如 more than/less than.

按 Rule8 计算 quoted text, proper name, formula 和数字加单位的词数.
括号短语在外句计 1 词; 内部句子单独检查.
Markdown 行内代码按项目约定视为不同字体的 quoted text.
表格单元和标题保留技术标签; 有意义的句子仍做长度检查.
Fenced code 属于受保护语法, 不属于英文正文.

## 中文翻译

每份英文原文同目录维护 `<stem>.zh.md`, 同次修改同步.
翻译全部正文, 保留事实, 状态, 条件, 不确定性和范围.
命令, 行内标识符, ID, 哈希, 数字和证据限制保持一致.
翻译链接标签, 存在中文 companion 时链接到译文.
英文原文为权威版本.
排除第三方子模块和 generated/vendored 依赖.

中文正文使用半角标点.
左括号前加空格, 其他标点后加空格.
中文字, 公式和英文单词之间加空格.
源码, 标识符, URL 和精确 payload 保持其语法.
应用 Humanizer-zh 删除空话和重复, 不改变证据强度.
保留必要否定约束和限制.

## 范围与历史信息

保留当前合同, 有用扩展边界, 实测证据和关键决策.
逐日修复经过保留在 Git 历史.
`docs/handoff.md` 记录当前状态和后续工作.
`docs/audit.md` 记录剩余问题和简短修复索引.
`docs/acceptance.md` 为统一证据索引.

主机路径, 地址, 进程身份和维护信息放在被忽略的 `LOCAL.md`.
完整原始证据放在被忽略的本地存储, 提交明确的 portable-derived 摘要.
区分原始 SHA-256 与派生文件哈希.
每份历史测量记录源码和配置.
旧结果不作为当前源码验收.

## 自动与独立检查

```bash
scripts/with-env.sh python scripts/check_docs.py
```

检查器检查全部项目自有, 跟踪或未被忽略的 Markdown 和当前跟踪文本.
检查翻译配对, 受保护代码相等, 显式数值, 本地链接 / anchor, 句长, 段落长度和标点.
校验术语表结构和登记词形, 拒绝已知不适合的通用措辞.
拒绝主机专属路径, 地址和 GPU 身份.
还检查 `LOCAL.md` 和本地证据的忽略规则.
Pre-commit hook 使用同一命令.

自动化不判断实际词义, 词性, 段落主题或完整翻译忠实度.
独立审查者必须对照官方词典审查英文, 对照英文审查中文.
在相关源码处检查技术术语必要性和算法含义.
直接使用官方标准; 私人参考副本保留在跟踪内容外.
检查通过本身不代表 STE 合规认证.
