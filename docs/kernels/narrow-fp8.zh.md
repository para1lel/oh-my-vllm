# 窄批次 FP8 投影测量

原生窄投影改变矩阵方向.
它保持 FP32 块缩放和 BF16 输出边界相同.
参见 [仓库 CUDA 路径](../../python/oh_my_vllm/kernels/cuda_backend/groupwise_transposed.cuh) 和 [Python 入口](../../python/oh_my_vllm/kernels/cuda_backend/groupwise.py#L211) <!-- source: def gemm_transposed( -->.
[源码绑定摘要](../evidence/narrow-fp8/verification.json) 记录原始文件, 已加载模块, 样本和验证限制.
最终源码的框架验收尚未完成.

## 数学依据

对于 `Y = X W^T`, 等价乘积为 `Y^T = W X^T`.
第二种方向把窄维度放到另一条矩阵轴上.
`Y^T` 的列主序视图与行主序 `Y` 使用相同存储.
这一等式不需要输出复制.

[CUTLASS 块缩放示例](https://github.com/NVIDIA/cutlass/blob/main/examples/81_blackwell_gemm_blockwise/README.md) 将这种方向作为窄矩阵的选项.
FP32 缩放仍在累加前作用于每个块乘积.
转换为二的幂缩放会改变该契约.
候选实现保持 FP32 缩放和单次最终 BF16 转换.

## 成对测量

采集使用行数 `1/4/20/32`, 输入宽度 `5120`, 输出宽度 `34816/16384/14336`.
它比较生产入口与原有填充 CUDA 路径.
十二种形状各有三轮, 每轮二十个交错测量对.
每个样本回放一次包含九十六次投影调用的图.
八份驻留权重构成约 0.6–1.4 GB 的工作集, 大于 L2 容量.

这些形状的完整投影 GPU 延迟降低 13.4%–18.4%.
每项节省时间的单侧 95% 置信下界均为正.
CUDA Events 包含 GPU 填充和输出工作, 不包含 Python 分派, 图捕获或 CPU 分配.
这些算子结果不能证明框架延迟降低.
[测量协议](../profiling/measurement.zh.md) 对分析器诊断与验收计时使用不同采集.

独立 CPU FP64 参考检查每种形状第一份驻留权重的六十四个输出列.
与原有 CUDA 路径的完整输出比较也通过.
计时采集使用全部八份权重. 它不为其中每份权重提供独立参考.

## 关键验证

[图回放测试](../../tests/numerical/test_fp8_transposed_replay.py) 在捕获后改变激活, 权重和两侧缩放张量.
测试检查调用者流, PDL 开关, 独立 GPU FP64 输出样本和两个入口路径的输出相等.
输出前后的存储保持相同.
采样列包含缩放块边界两侧及最后一个输出列.
故障测试在启动前拒绝别名, 未对齐地址, 错误输出形状和错误缩放步长.
两个回放案例通过 Compute Sanitizer, 错误数为零, 包含 PDL 开启和关闭.

完整诊断算子矩阵的 539 个案例全部通过, 无干扰.
未提交源码结果保持 `passed=false` 和 `selected_passed=true`.
单独的回放测试覆盖原有正式矩阵未包含的窄输出形状.
容量, 服务, 一小时运行和十五行框架矩阵仍需最终源码验证.

## 经验

普通模式 32768 输入, 4096 输出, batch 1 的框架诊断包含两次预热和五次测量.
其 prefill 和 decode 比值为 4.461 和 2.203. 波动通过, 但延迟检查失败.
结果保持 `diagnostic=true` 和 `passed=false`. 它不能替代最终源码验收.

通过生产入口的图回放测量方向选择, 包括 GPU 填充和输出工作.
推理负载读取多份不同权重时, 保持权重工作集大于 L2 容量.
用独立参考比较改变输入后的回放, 并明确检查缩放块边界.
将已加载模块哈希绑定到其源码和头文件哈希.
算子计时改善不能替代框架门槛.
