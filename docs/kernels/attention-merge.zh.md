# 注意力分段合并

[自有注意力源码](../../python/oh_my_vllm/kernels/cuda_backend/operators/decode_attention.cuh)将 128 个分段的加权和分配给八个 warp 和四个值分块.
最大值与权重分母保持原有归约顺序, FP32 值总和的分组发生变化.
最终 BF16 边界和数值容差不变, 空头精确输出零.

## 数值检查

[合并契约测试](../../tests/numerical/test_attention_merge_replay.py)使用独立 FP64 参考比较完整加权均值.
五种形状覆盖抵消, 单个主导分段, 混合空分段和空头.
检查包括全新写入, 输出哨兵, 输入不变, 以及在非默认流上改变输入后的图重放.

主分支通过五项全新内存检查, 115 项选定 GPU 测试, 以及全部 539 项算子数值诊断.
CPU 通过 1682 项测试和 153 项子测试, 无跳过. 完整数值和整模型报告保留 `diagnostic=true` 和 `passed=false`.
[证据摘要](../evidence/attention-merge/verification.json)绑定源码, 模块, 原始结果和独立审查.

## 完整操作对照

每个样本执行注意力部分计算与合并, 使用八份独立且大于 L2 的 KV 缓存.
上下文为 32768 个 token, 包含 24 个查询头, 四个 KV 头, 批次分别为一, 二, 四.
完整 FP64 注意力参考在计时前及改变输入后的重放后, 检查全部八份输入.
目标哨兵, 完整写入, 输入字节和调用流行为检查也均通过.

三轮测量各使用二十个交错配对, 每个样本执行一百次完整操作.
平均收益分别为 3.557, 4.912, 10.629 微秒, 单侧 95% bootstrap 下界分别为 3.544, 4.882, 10.552 微秒.
平均延迟降幅约为 9.13%, 7.24%, 8.82%.
这些设备区间不包含查询准备和主机调度.

## 对照模块隔离

首次双模块批次四内存检查在 CUDA 启动时失败, 原始日志和空结果文件均保留.
符号证据指出, 两个库共享 GNU-unique 的函数局部标志. 其一次性配置可能跳过第二个模块的共享内存扩展上限设置.
全新实验构建为两个对照库都增加 `-Xcompiler=-fno-gnu-unique`.
只读地址检查证明标志地址独立, 全部 482 个设备函数体及资源与对应原始构建相同.

随后, 两种 PDL 设置下的六项全新完整操作内存检查全部通过.
生产代码保留原有编译选项, 主分支只加载一个模块, 并通过自身的全新内存和数值检查.
该实验不声称生产双模块路径存在缺陷.

## 整模型范围

同一 GPU 上的普通模式 32768/4096 批次一采集, 各包含两次预热和五次测量, 使用独立缓存及相同发布二进制.
采集前后源码和检查点身份一致, 稳态审计通过, 无抢占或进程泄漏.
预填充中位数分别为 1.896502455 和 1.901747655 秒, 解码中位数分别为 34.079205395 和 33.769918883 秒.
候选比值分别为 4.305, 2.181, 两项延迟门槛均失败, 所有波动检查通过.
观测到解码降低 0.908%, 预填充增加 0.277%. 这两组顺序采集不能确立整模型因果归因.

最终源码下的十五组工作负载, 27 项延迟门槛, 以及两种模式的整本书长跑仍待完成.
操作收益不能代替整模型验收, 也不能证明关键路径收益.
