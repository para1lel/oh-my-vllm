# GDN 精度路径的持久状态

当一个序列, 一个头的所有分块都走精度路径 `1` 时, 扫描会在分块之间将 FP32 状态保留在寄存器中.
其他序列仍走原有混合路径循环. 路径检查在设备上执行.
逐 token 递推, 八 lane 归约顺序, FP32 状态和 BF16 输出边界保持一致.
这条路径不读取内部 BF16 状态镜像, 因此省去反复写入镜像的操作.

参见[扫描](../../python/oh_my_vllm/kernels/cuda_backend/operators/gdn_chunk.cuh), [精度操作](../../python/oh_my_vllm/kernels/cuda_backend/operators/gdn_precision.cuh)和[关键测试](../../tests/numerical/test_gdn_prefill_persistent.py).
[源码绑定摘要](../evidence/persistent-state/verification.json)记录原始源码, 加载模块, 验证, 测量和失败尝试的对应关系.

## 算子测量

比较使用同一次模型观测运行保存的三份连续 GDN 输入快照, 输入为重复 token.
每个完整操作测量三轮, 每轮二十个交错配对样本, 每个图样本包含一百次完整操作.
GPU 事件时间包括归一化, 准备, 投影和扫描.
主机分配, 图捕获和派发不计入该时间.

| 调用序号 | CUDA 基线 | 持久状态 | 降幅 |
| --- | ---: | ---: | ---: |
| 0 | 8.433 ms | 8.388 ms | 0.53% |
| 15 | 16.049 ms | 14.830 ms | 7.60% |
| 47 | 16.075 ms | 14.846 ms | 7.65% |

三组节省时间的置信下界均为正.
快照没有标识物理层编号, 检查点字节哈希或其他提示分布.
比较基线是仓库 CUDA, 并非独立的长序列 FP64 参考.
连续快照不能验证原始模型的打包步长.

十六 lane 候选改善第一份输入, 但另外两份更慢, 已被排除.
保留它的全部原始测量, 不只选取有改善的输入.

## 关键验证

十二项外部新进程内存检查通过, 错误数为零.
全部 539 项算子数值用例通过独立输出, 状态, 舍入和输入修改检查, 未检测到干扰.
该未提交源码的测量属于诊断. 保留 `passed=false`, `selected_passed=true` 的原始字段.
另有 105 项选定 GPU 测试通过.

五项新增测试要求每个有效分块都走精度路径 `1`.
覆盖两 token 尾段的近完全抵消, 783/785 token 的填充与未对齐行, 以及 16/48 头的实时图重放.
序列偏移变化时保留空序列. 每次操作保留本次输入, 初始状态, 填充和输出哨兵.
独立参考以及现有数值, 状态容差继续生效.

主工程新构建模块通过全部五项内存检查, 以及 588 项数值测试和六项子测试.
其构建输入与已审查外部候选相同, 二进制标识另行记录.
混合路径和路径变化测试继续保留.

六项最大上下文用例在 CPU 超时夹具修复前通过. 运行时源码保持一致.
修复后的夹具仅在 CPU 子进程范围内清除 GPU 可见环境.
完整剩余重跑通过 2308 项测试和 153 项子测试.
该分区验证属于诊断; 保留原始失败记录.

## 框架验证

ordinary 模式的 32768 输入, 4096 输出, batch 1 比较使用相同 GPU, 检查点字节和 release binary.
每次采集包含两次完整预热和五次测量, 采集期间源码不变.
独立缓存通过稳态审计.

Prefill 中位数从 1.959 秒降至 1.899 秒, 改善 3.06%.
Decode 中位数分别为 33.970 和 33.947 秒.
候选两阶段比值为 4.300 和 2.192, 两项延迟检查仍未通过下界两倍门槛, 两项波动检查通过.
这项结果证明该负载的 prefill 有实测改善, 不代表完整矩阵或最终源码验收通过.

首轮基线与候选测量因测量期间共享缓存文件变化, 未通过稳态审计.
保留两次完整原始尝试. 仅凭缓存时间不能确定写入者.
下一组完整比较分别使用独立的 native, Triton, 编译器和驱动缓存.

这些诊断结果不能作为最终源码验收.
十五行框架负载, 容量与服务检查, 以及之后的一小时负载仍需基于最终源码验证.
数值容差和理论方程保持一致.
