## 输入范围

带观测的普通模型运行保存 GDN 调用索引 `0/15/47` 的输入.
它使用重复 `32768` 次的 token `42` 和手工提供的缓存表.
快照包含完整初始状态和序列偏移.
它们不标识物理层 ID, 检查点字节哈希或提示分布.
运行包含观测开销. 其耗时不是验收延迟.

部分 head 衰减很弱. 平均衰减不能约束更早的状态贡献.
删除历史或传递项之前, 必须比较完整状态.

## 有限历史

一个候选从有限前置窗口执行逐 token FP32 递推.
窗口未包含序列起点时, 它使用零状态.
窗口包含每段之前的 `128/512/2048` 个 token.
九项模型输入与仓库 CUDA 的比较全部失败.
最终状态 NRMSE 为 11.22%–93.26%.
本次采集中, 延长窗口没有纠正失败.

这些比较不使用独立长序列 FP64 参考.
它们足以根据现有运行时契约拒绝候选.
结果不授权衰减截断或新的容差.

## 逐 token FP32 前缀与矩阵后缀

一个混合候选在每个 chunk 使用逐 token FP32 前缀和 FP32 WY 矩阵后缀.
初始抵消采集通过 24 个案例. 扩展采集通过 36 个案例.
这些案例的抵消从首个 token 开始.
九项模型输入比较也通过, 但候选耗时 21.13–24.05 ms, 仓库 CUDA 为 8.46–16.07 ms.

后续测试把每个 chunk 前八个 token 的 beta 设为零.
十二项延迟抵消比较的最终状态检查全部失败.
最终状态 NRMSE 为 6.06%–69.85%, 但输出绝对容差检查通过.
固定的逐 token FP32 前缀不能防止这些最终状态失败.
应独立于普通随机输入验证来测试抵消位置.

## 原生 FP64 面板

一个八 token 的 WY 候选使用原生 FP64 矩阵计算传递状态.
四项延迟抵消案例全部通过独立 FP64 参考.
三项完整模型输入比较通过仓库 CUDA 参考.
完整候选耗时 36.47–36.53 ms, 基线为 8.45–16.07 ms.
另一项保留状态累加器片段的候选耗时 39.33–39.60 ms.
两项候选均未选用.

一次诊断扫描的占用率为 16.08%, Tensor Core 活跃度为 12.20%, DRAM 活跃度为 0.49%.
Nsight Compute 在不控制缓存和时钟的情况下采集 18 次回放.
其 34.89-ms 耗时属于分析器诊断, 不是验收计时样本.
低 DRAM 活跃度不能证明增加暂存会降低延迟.
再次选择调度方案前, 应结合源码和设备指令检查指令依赖停顿.

首次原始构建的共享缓冲区太小. 它没有执行.
修正构建具有单独的源码和模块身份.
首次计数器尝试没有选中内核. 两份原始失败记录均保留.

## 理想算术界与 FP32 舍入

理想算术下, 状态行映射为 `A = lambda * (I - beta * k k^T)`.
其谱范数为 `lambda * max(1, abs(1 - beta * ||k||^2))`.
这个理想算术界不能证明经过舍入的 FP32 递推具有相同界.

一个 CPU 反例把初始状态的一个值从 `1` 改为其下一个 FP32 值.
初始差值为 `1.1920929e-7`. 一个舍入后的状态结果改变了 `1`.
BF16 输出差值为 `0.0625`, 超过所提界 `1.0535587e-8`.
独立精确有理数算术验证记录中的每次 FP32 舍入操作.
这是 CPU/libm/软件证明, 不是 GPU 执行或生产失败.

误差保护必须包含舍入误差, 每个输出及最终状态的相对和绝对限制.
只有理想算术残差并不足够.
回退必须从未改变的初始状态重新开始, 并替换全部候选输出.
这些条件是未来保护机制的要求, 不是已验证的实现.
