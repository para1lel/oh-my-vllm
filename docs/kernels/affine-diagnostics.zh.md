# 原生矩阵与仿射扫描诊断

这些实验没有选用新的生产实现, 也不能证明框架验收通过.
[绑定源码的摘要](../evidence/affine-diagnostics/verification.json) 绑定原始源码, 已加载模块, 输入, 结果和失败尝试.
使用 [测量方法](../profiling/measurement.zh.md) 和 [算法调研](optimization.zh.md).

## 完整仿真成本

[cuBLAS 指南](https://docs.nvidia.com/cuda/archive/13.1.0/cublas/index.html#floating-point-emulation) 描述通过三个 BF16 分量和九个乘积仿真 FP32.
输入重构不能证明 IEEE FP32 合规, 也不能证明完整 GDN 的精度.
特殊值检测和输出修正的成本可能超过矩阵计算.

七个形状各测试三种模式, 共进行 21 次 CPU FP64 结果比较.
每次比较检查前八个 batch. 如果 batch 数少于八, 则检查全部 batch.
固定的有限随机输入通过探针容差. 未检查极端值和溢出.

对 24576 个 `128 x 128 x 64` 矩阵 batch, 使用默认特殊值处理的 eager 仿真耗时 9.654 ms.
其时序图包含约 0.517 ms 矩阵计算, 1.624 ms 检测和 7.508 ms 输出修正.
这些 profiler 区间只用于诊断, 不是正式计时样本.

另一次仅有限值探针关闭特殊值处理. 相同形状耗时 0.545 ms, 原生 FP32 为 1.567 ms.
有限输入本身不能避免中间结果溢出, 也不能证明 signed-zero 行为正确.
该探针没有提供生产输入合同.

一个仅有限值的 FP64 探针对四个更大形状比较原生和 eager 仿真模式.
八次前八 batch 比较全部通过 CPU FP64 探针容差.
原生中位数为 0.051–3.305 ms. eager 仿真中位数为 1.021–49.503 ms.
所采样的仿真时序图包含缩放, 打包, 矩阵计算和输出转换.
关闭特殊值处理后, eager 仿真在这些形状上仍慢于原生 FP64.

## 仿射扫描与布局

一个 chunk 通过矩阵和位移映射输入状态: `next_state = state * T + D`.
chunk 复合给出相邻 chunk 的映射. 排他前缀为各 chunk 提供输入状态.
候选保留完整初始状态. 它们没有使用衰减截断.

第一个候选复制矩阵视图, 拼接前缀状态, 并使用加法 kernel.
后续候选使用矩阵视图, 以及输入和输出矩阵不同的矩阵 epilogue.
布局和矩阵算法选择都发生变化. 测量不能说明哪项修改导致计时差异.

| 32768-token 候选 | CUDA 基线 | 候选中位数 | 预处理在捕获内 |
| --- | --- | --- | --- |
| 首个 BF16 仿真链路 | 16.050 ms | 20.696 ms | 否 |
| pointer-array 布局 | 16.062 ms | 13.336 ms | 是 |
| strided 布局 | 16.066 ms | 11.921 ms | 是 |

每种配置有十个交错样本. 这不是正式配对准入协议.
第一个候选没有 query 变化时的重放验证. 它在捕获之前缓存已归一化 query.

三个 768-token 模型输入前缀和一个合成 384-token 案例通过独立 FP64 比较.
32768-token 案例使用仓库 CUDA, 没有使用独立长序列参考.
候选处理单序列的完整 chunk. ragged 尾部和多序列没有验证.
对于部分 chunk 数, strided 原型会复制矩阵视图. 五个 chunk 和两个 head 触发其无复制断言.

## 抵消与重放

[抵消测试](../../tests/numerical/test_gdn_prefill_replay.py) 检查初始状态几乎完全消除后, 仍然很小但非零的最终状态.
八个诊断工作负载使用零 value, 零 decay, 近似相等的 key 和非零初始状态.
它们包含 384-token 和 4096-token 输入.

仓库 CUDA 通过全部八个独立 FP64 比较.
strided BF16, 首个原生 FP32 和首个 BF16 仿射候选均在全部八个最终状态比较中失败.
pointer-array 候选未参与这次抵消采集.
strided 候选的状态 NRMSE 为 4.20%–173.66%.
输出通过绝对容差. 只有最终状态比较失败.

原生 FP32 矩阵计算也失败. 结果不能证明 BF16 仿真或地址映射导致失败.
分别检查上游 projection 精度和仿射复合舍入.
没有选用任何仿射候选.

strided 候选通过三次 384-token 图重放, 使用一个 query head 和两个 value head.
其中两次重放在原地改变 query, key, value, gate 和初始状态之后执行.
序列偏移和形状保持相同. 此结果不能修正抵消失败.

## 应保留的方法

测量预处理和完整矩阵链路. 使用设备时序图定位复制和 elementwise kernel.
如果配对测量显示完整算子收益, 使用矩阵视图和 epilogue.
分别检查输入的初始状态, 最终状态抵消和输入变化后的图重放.
即使候选有计时收益, 也保留失败的数值结果.
选用生产实现之前使用不变的合同, 然后关闭 profiling, 重复框架验收.
