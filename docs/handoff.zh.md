# 交接记录 — 2026-09-23

## 当前状态：CUDA 迁移完成

B200 上自定义 kernel 的默认后端已为 CUDA。Python 启动前设置
`OH_MY_VLLM_KERNEL_BACKEND=tilelang` 可使用唯一一份冻结对照实现。
运行时身份报告实际的进程级选择，不会静默回退。Rust 仍负责服务/调度/逻辑 KV，
Python 负责 GPU 计算，没有重新引入 vLLM 运行时、源码或环境依赖。

干净提交 `c36d1c9` 显式选择 CUDA 时，通过全部 **147项算子**和 **12组框架性能**
测试。每项算子通过三轮、每轮20对交替测量，且单侧95% bootstrap 收益下界大于零。
框架吞吐为冻结 vLLM baseline 的97.52–125.09%，TTFT 为76.01–97.50%，各组均满足
未改变的10%稳定性规则。保留此前稳定性失败的完整数据和三组物理 CPU 核重叠的
排除记录，没有重跑 baseline。历史173项清单早于注意力准备融合，不是当前清单。

十二组工作负载为输入32768的 ordinary/MTP/prefix、各 batch1/2/4，加上仅
ordinary 的输入131072、batch1/2/4，输出均为4096。六组普通/MTP 的输入258048、
输出4096边界测试也均完成，无 OOM/抢占。PyTorch reserved 峰值为134.69GB，
这个口径不是整卡显存占用。

最终默认选择下，正确性通过 **174项测试及31个子测试**，没有放宽数值参考或容差。
切换默认值没有改变实测 CUDA kernel、模型或 dispatch 实现。真实模型 FP64
探针、普通/MTP 真实文本隔离、前缀复用、强制抢占均通过。MTP4 约束、生命周期
及长严格 JSON 请求复用通过。最终服务运行未设置后端、CUDA_HOME 或 TVM 架构
变量，验证了实际默认行为，并再次通过十二项约束和生命周期测试。

更新文档后的 oh-my-pi Chat/Responses 读回通过核心任务：各有九次成功 read，
5/3次真实模型请求和非零 MTP 接受数量。两者都读取必要源码，并区分当前147项
与历史数量。保留回答局限：Chat 工作负载措辞不够准确；Responses 混淆 Rust
调度与 Python prefill 排序，并给出历史性能命令；两者都在自身服务运行时引用
