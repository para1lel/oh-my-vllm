# 文档规则

项目的所有英文文档遵循 [ASD-STE100 Issue 9](https://www.asd-ste100.org/assets/files/ASD-STE100_ISSUE9.pdf).
按规定的词义和词性使用批准词汇.

每个[项目术语](glossary.zh.md)仅使用词表中的含义.
不将普通词汇重新声明为技术术语.

每项事实只在一个位置维护. 其他位置使用链接.
README 提供使用者信息. CONTRIBUTING 提供贡献流程.

保留适用的实现说明, 以及每种获批工作负载最近一次完成的结果.
删除不再适用的说明, 结果和文件. 在同次修改中更新其链接.

根目录 AGENTS 给出适用于所有目录的规则. 子目录 AGENTS 给出对应目录树的规则.
只有目录存在局部规则时才添加子目录指南.

每篇英文 Markdown 文档不超过 2000 个英语单词.
统计可见正文, 标题, 表格文字和行内标识符.

不统计围栏代码和链接目标.
操作说明每句不超过 20 个词. 每句只描述一个操作.

描述性句子不超过 25 个词. 描述性段落不超过 6 句.

在同目录的 `<stem>.zh.md` 文件中提供完整中文翻译.
保持事实, 条件, 不确定性, 命令, 标识符, 数字和标题层级一致.

以英文文档为源文件. 存在对应中文文件时使用中文链接.
中文使用半角标点. 中文与英文或数字之间留空格.

实现细节使用源码链接. 不将实现复制到正文.
每个源码行链接使用在对应源文件中仅出现一次的文本锚点.

文档 hook 自动更新行号.
主机路径和地址放在被忽略的本地配置中.

获批的性能文档使用 [nightly 记录策略](deepseek-v41/validation.zh.md).
不添加无关测试结果, 原始日志或交付历史.

由另一个代理进行文档审查. 核对词义, 词性和翻译.
以官方标准为依据. 自动检查不能覆盖全部 STE 规则.
对照英文核对中文内容.
