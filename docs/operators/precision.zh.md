# 算子数值门槛

[Microbench 设计](microbench.zh.md) 规定固定输入和独立的 PyTorch fixture.
本文规定精度策略 `operator-precision-v1`.
[门槛提议工具](../../development/operators/budgets.py) 将此策略应用于存储的 FP64 参考数组.
工具写入新的外部文件以供审查.
工具不读取候选实现输出, 也不修改已批准的门槛.

## 字段门槛

使用 `u32 = 2^-24`, `u16 = 1/256` 和 `u8 = 1/16` 作为 FP32, BF16 和 E4M3 正规数的舍入单位.
这些单位用于制定工程精度门槛.
这些门槛不是最坏情况舍入误差的证明.
投影的条件性质, 非线性计算和重复层可能放大舍入误差.
对投影结果, 残差和持久状态使用不同门槛.

`P` 是对应字段和序列的 FP64 参考值的最大绝对值.
对 chain 的 hidden/logit 字段, 按每个请求和每个 draft 步骤分别比较.
每次比较只使用该步骤的量级.

| 字段 | 归一化 L2 门槛 | 最大绝对误差 |
|---|---|---|
| FFN 残差 | `u32` | `u32 * P` |
| 其他残差 | `u16` | `u16 * P` |
| 最终 hidden 和 hidden cache | `2*u16` | `4*u16 * P` |
| Output logits | `4*u16` | `8*u16 * P` |
| MTP context 投影 | `4*u16` | `8*u16 * P` |
| Vision hidden | `4*u16` | `8*u16 * P` |
| FFN value | `u8` | `2*u8 * P` |
| FA value | `0.1` | `2*u8 * P` |
| GDN value | `0.1` | 通道 `j` 使用 `2*u8 * P_j` |
| BF16 KV, FP32 recurrent state, BF16 convolution state | `u8` | `2*u8 * P` |
| 单步 MTP draft hidden/logits | `u8 + 4*u16` | `2*u8 * P` |
| 四步 draft chain hidden/logits | `2*u8` | `4*u8 * P` |

仅使用 BF16 的路径采用比完整 FP8 子层更小的门槛.
单步 draft 门槛包含 FP8 子层前后的 BF16 输入投影, 归一化和词表投影.
Chain 门槛更高, 因为 draft 步骤会重复.
这些路径的持久状态门槛保持不变.

对于 GDN 输出投影 `y = W*x`, 从 FP64 参考值计算 `R_j = sqrt(sum_i (W_ji*x_i)^2)`.
对每个序列使用 `P_j = max(P, max_t R_tj)`.
在参考清单中为每个序列保存一个 `max_t R_tj` 值向量.
门槛提议工具从这些值计算 `P_j`.
将各通道的门槛应用于该通道的全部输出行.

只有条件尺度超过原序列峰值的通道才使用更大的门槛.
此工程策略考虑投影敏感度.
它不是输入误差同向叠加时的最坏情况界限.
归一化 L2 和持久状态门槛仍然适用.

使用 `1e-6` 作为 RMS 分母下限.
表中计算的门槛更小时, 使用 `1e-7` 作为最大绝对误差门槛下限.
参考值 RMS 不超过 `1e-6` 时, 还要求最大绝对误差不超过 `1e-6`.
所有条件都必须通过.
拒绝非有限值.
对整数输出, RNG 计数器, 分配的槽位和未写入的存储进行逐位相等比较.

## 概率门槛

Output 采样用例保留惩罚, 掩码和截断.
MTP draft 用例使用 temperature 1, 不使用 top-k, top-p 或 min-p 截断.
这些用例保留惩罚, 掩码和随机选择.
Output 用例独立于 MTP 计算检查不连续的截断行为.

三个 chain 数值用例为每个请求使用一个固定的允许 token.
各请求使用不同 token. 此 token 不是请求的初始输入 token.
使用此固定路径, 测试在四个相连步骤中比较完整 hidden, logits, state 和 guards.
采样用例检查 token 选择. Worker 行为测试检查 chain 步骤间的 token 反馈.

| 概率路径 | 归一化 L2 门槛 | 最大绝对误差和总变差 |
|---|---|---|
| BF16 output | `0.03125` | `0.0078125` |
| MTP | `0.5` | `0.125` |

总变差是一个词表行内概率绝对误差之和的一半.
将其门槛应用于每一行, 包括每个验证行.
选中概率也使用相对误差和最大绝对误差门槛.

平滑的 MTP 概率还必须处于 softmax 扰动范围内.
令 `e` 为已批准的 logit 绝对误差门槛, 再计入重复惩罚的敏感度和温度缩放.
对于参考概率 `p`, 使用:

```text
r = exp(2*e)
lower = p / (p + (1-p)*r)
upper = p*r / (1-p+p*r)
```

允许这些端点周围有 32 个 FP32 epsilon 的余量.
即使此范围较宽, 独立的概率门槛仍然适用.

要求概率非负, 且被掩码排除的 token 的概率严格为零.
要求每行概率和与一的差不超过 32 个 FP32 epsilon.
Greedy 行必须严格为 one-hot.
选中概率必须等于选中 token 对应的概率.

## 固定随机选择

在评估候选实现之前, 根据 FP64 分布选择种子.
将这些种子和预期的计数器更新存入 fixture.
对每个随机样本, 存储选中 token 两侧的 CDF 端点.
观测候选实现时, 在 native 调整后分数排序中使用同一个参考选中 token 来取得端点.
此排序包含惩罚, 掩码和 token 同分处理.

端点误差预算取概率总变差上限与参考区间宽度三分之一中的较小值.
要求参考随机数到每个端点的距离大于此预算加 32 个 FP32 epsilon.
还要求它到每个正概率 CDF 边界的距离大于 `0.01`.
候选实现必须同时通过两个端点误差门槛和精确 token 选择检查.
此检查覆盖允许概率误差中的一个稳定子集.
允许范围内的 logit 误差仍然可能改变 token 排序.

Acceptance fixture 还记录随机数到接受比值和残差或 bonus CDF 边界的距离.
这些固定的二进制分数概率不依赖上游投影误差.
精确 token, count, slot 和 RNG 要求仍然必须满足.

修改 fixture 或策略之前, 先审查失败的门槛.
不要自动提高门槛来接受候选实现.
