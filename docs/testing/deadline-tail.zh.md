# 采集截止时的收尾请求

一小时窗口由采集器的单调时钟确定结束.
原生 goal 暂停和 RPC abort 在截止之后发生, 随后由同一服务排空请求.
采集器停止客户端的行为不改变服务端记录的请求状态.

服务端已完成的请求可能在客户端于该边界关闭时丢失 SSE 终止事件.
只有[截止证据检查器](../../benchmarks/agentic_deadline_evidence.py)可以验证这种结果.
它要求原始控制命令字节, 成功确认, 唯一的原生中止结果, 以及同一请求的原始 SDK 导出.
Goal, prompt, session, response, API, provider, model 和时钟必须一致.

Wire 必须记录下游断开和合法的 SSE 前缀.
服务端实际输出必须保持在原始请求的输出预算内.

[RPC 记录器](../../benchmarks/agentic_rpc_evidence.py)在不改变原生协议字节的情况下记录控制动作时间.
单调时钟决定先后顺序.
两毫秒限制用于检查时间戳精度和时钟偏移.
SDK 完成必须晚于截止和 abort 发送开始.

代理在下游写入失败时记录墙钟和单调时钟.
断开必须晚于 abort 发送开始. Handler 清理时间不能替代它.
超过两毫秒的时钟差异会导致验证失败.

将这些结果与成功的流和服务端取消分开报告.
请求散点图不包含这些结果, 保留其原始指标和字节.
成功的流必须有全部终止事件, 且 usage 与 token 计数一致.
证据缺失或未绑定唯一请求时, 验证失败.

[关键回归案例](../../tests/tooling/test_agentic_deadline_evidence.py)覆盖两个 API, 并拒绝改变的身份, 时钟, 字节, 确认和 SDK 结果.
没有采集控制时间戳的历史记录保留其原始结果.
