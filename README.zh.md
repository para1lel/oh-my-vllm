# oh-my-vllm

本项目提供在单张 NVIDIA B200 上运行 Qwen3.8-27B-FP8 的 Rust 服务.
Python worker 加载模型, 执行文本, 图片和视频推理.
支持普通解码或 MTP4, 并提供约束解码.

安装, 命令和 HTTP 请求见[服务指南](docs/serving.zh.md).

## 性能测量

2026-10-17 的测量使用单张 NVIDIA B200 和 Qwen3.8-27B-FP8.
运行时源码见版本 [`d516bf6`](https://github.com/para1lel/oh-my-vllm/commit/d516bf6ec62c451158e4f160ed6bc0f587165e02).

### 算子

下表为[建模负载](docs/operators/evaluation.zh.md)上的期望 roofline 效率.
每种形状使用冷权重, 预热 2 次, 测量 5 次.

| Serving 算子 | Eager | CUDA Graph |
|---|---:|---:|
| FFN | 48.9% | 54.4% |
| FA | 34.4% | 38.1% |
| GDN | 25.1% | 28.5% |
| Vision | 15.2% | 16.1% |
| 采样 | 65.2% | 68.7% |
| MTP context | 23.6% | 27.8% |
| MTP draft | 63.9% | 69.3% |

全部 7 个算子均通过规定的小形状数值检查, 计时覆盖完整.
仅采样和 MTP draft 在两种执行模式下均达到 60% 性能门槛.
整套算子未通过验收.

### 端到端 HTTP

测试不复用前缀缓存, token 预算为 32768, 最多同时运行 4 个请求.
缓存容量为 1024 个 FA block 和 128 个 GDN slot.
每个请求使用文本输入和贪心采样, 输出 8192 个 token.

每种模式对 batch 1, 2, 4 各运行 1 次预热.
每个预热请求输入 64 个 token, 输出 16 个 token.
每种配置正式测量 1 轮.
时间单位为秒. HTTP 时间从并发提交请求计至客户端收到全部输出.

Roofline 时间为 trace 中各 serving 算子时间下界之和, 使用实测 MTP 接受数.
效率为 `roofline_seconds / HTTP_seconds`.

| 模式 | Batch | 每请求输入 token 数 | HTTP 时间 | Roofline 时间 | Roofline 效率 |
|---|---:|---:|---:|---:|---:|
| 普通解码 | 1 | 32768 | 65.38 | 31.87 | 48.75% |
| 普通解码 | 2 | 32768 | 81.26 | 35.11 | 43.20% |
| 普通解码 | 4 | 32768 | 91.65 | 41.57 | 45.36% |
| MTP4 | 1 | 32768 | 22.37 | 9.86 | 44.07% |
| MTP4 | 1 | 65536 | 30.35 | 11.15 | 36.74% |
| MTP4 | 1 | 131072 | 45.74 | 15.19 | 33.20% |
| MTP4 | 2 | 32768 | 30.67 | 11.24 | 36.63% |
| MTP4 | 2 | 65536 | 47.67 | 14.06 | 29.50% |
| MTP4 | 2 | 131072 | 76.32 | 20.46 | 26.80% |
| MTP4 | 4 | 32768 | 47.89 | 14.17 | 29.58% |
| MTP4 | 4 | 65536 | 70.58 | 20.07 | 28.43% |
| MTP4 | 4 | 131072 | 133.70 | 32.16 | 24.06% |

全部 28 份正式测量响应均输出 8192 个 token, 缓存前缀 token 数为零.
全部 12 种配置均低于[端到端性能的 60% 门槛](docs/performance.zh.md).
