# oh-my-vllm

本项目提供在单张 NVIDIA B200 上运行 Qwen3.8-27B-FP8 的 Rust 服务.
Python worker 加载模型, 执行文本, 图片和视频推理.
支持普通解码或 MTP4, 并提供约束解码.

安装, 命令和 HTTP 请求见[服务指南](docs/serving.zh.md).

## 性能测量

2026-10-18 的测量使用单张 NVIDIA B200 和 Qwen3.8-27B-FP8.
运行时源码版本为 [`6720f42`](https://github.com/para1lel/oh-my-vllm/commit/6720f42048ce3e1370c4e38cba54d366eb383fd3). 数值在计算完成后舍入显示.

### 算子

下表为[建模负载](docs/operators/evaluation.zh.md)上的期望 roofline 效率.
按各 case 的建模调用次数, 对各自效率取加权算术平均.
每种形状使用冷权重, 预热 2 次, 测量 5 次, 并取实测时间中位数.
[算子评估器](development/kernels/__main__.py)在 Graph 捕获前对每种形状先执行一次 eager 运行.
该次运行不计入实测时间.

| Serving 算子 | Eager | CUDA Graph |
|---|---:|---:|
| FFN | 49.63% | 55.30% |
| FA | 35.77% | 40.31% |
| GDN | 27.15% | 31.72% |
| Vision | 11.09% | 11.39% |
| 采样 | 65.22% | 68.65% |
| MTP context | 21.70% | 33.54% |
| MTP draft | 44.97% | 51.26% |

全部 7 个算子的小形状数值检查结果符合规定要求.
每种执行模式的测量均包含全部 75 个建模 case.
14 组算子及执行模式结果中, 4 组达到 50% 门槛.
数值检查前记录的 SM 时钟有 1965 MHz 和 1155 MHz 两种, 因此完整算子审计未通过.

### 端到端 HTTP

请求使用文本输入, 贪心采样, 且不复用前缀缓存.
每个调度步骤的 token 预算为 32768.
同时运行的请求数上限为 4.
缓存容量为 1024 个 FA block 和 128 个 GDN slot.

每种模式对 batch 1, 2, 4 各运行 1 次预热, 每条预热请求输入 64 个 token, 输出 16 个 token.
每种配置正式测量 1 轮.
计时前构造 prompt 文本.

HTTP 时间包含请求线程创建, 服务端请求准备, 排队, 完整推理, 传输, JSON 解析及线程退出.
Roofline 时间是执行 trace 中各 serving 算子下界之和, 使用实测 MTP 接受数.
效率为 `roofline_seconds / HTTP_seconds`.
